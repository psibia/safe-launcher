# Безопасный лаунчер

(проект `KillSwitchLauncher`)

WPF-лаунчер (.NET 8) для корпоративных утилит, которые должны работать только внутри VPN.
Запускает программы только при активном VPN, запоминает их процессы и, если VPN пропадает,
принудительно их завершает (опция «Kill-Switch»).

## Сборка и запуск

Нужен .NET 8 SDK для Windows (или Visual Studio 2022 17.8+ с нагрузкой «Разработка классических приложений .NET»).

```powershell
git clone https://github.com/psibia/safe-launcher.git
cd safe-launcher
dotnet run --project KillSwitchLauncher
# или самодостаточный exe:
dotnet publish KillSwitchLauncher -c Release -r win-x64 --self-contained -p:PublishSingleFile=true
```

Либо откройте `KillSwitchLauncher.sln` в Visual Studio и нажмите F5.

Готовый установщик для Windows — в разделе [Releases](https://github.com/psibia/safe-launcher/releases).

## Тесты

В решении есть проект `KillSwitchLauncher.Tests` (xUnit). Запуск: Visual Studio → «Тест» → «Обозреватель тестов» → «Запустить все», или в консоли:

```powershell
dotnet test
```

Проверяются журнал событий, настройки, обновления (разбор релизов, загрузка с проверкой SHA-256), правила VPN и распознавание адаптеров, одна копия лаунчера, Kill-Switch на настоящих процессах, логика главного окна, ярлыки и значок в трее. Тесты работают во временной папке и не трогают настройки лаунчера. Для проверки Kill-Switch сборка тестов сама служит маленькой программой-«приложением», поэтому настоящие программы не закрываются.

## Интерфейс

Стиль «мягкой панели»: светло-серый фон окна, большая внутренняя панель со скруглением, белые карточки с крупным радиусом и мягкими тенями, градиент голубой → фиолетовый как акцент, крупные жирные заголовки, кнопки-«таблетки».

* Всё содержимое стоит на одной сетке: шапка, заголовок, кнопки, плитки и карточка настроек начинаются и заканчиваются в 40 px от краёв окна. При наведении у плиток меняется только тень и подсветка круга под иконкой, сами плитки не двигаются.
* Шапка в одну строку. Статус VPN в ней: компактная «таблетка» с градиентным кругом (зелёный или красный) и замком и только надписью «VPN подключён / отключён»; подробности во всплывающей подсказке.
* Плитки: иконка приложения в сером круге, название под ней (до двух строк). Подсказка с путём появляется под плиткой, не перекрывая иконку.
* Переключатели: «таблетка», во включённом состоянии с градиентом. Длинные подписи переносятся внутри строки и не залезают под переключатель.
* Меню по правому клику на плитке: своё оформление, название приложения в заголовке, иконки пунктов, красный пункт «Убрать из лаунчера».
* Подключение и обрыв VPN, запуск и добавление приложений сопровождаются уведомлением-«таблеткой» с цветным кругом. Оно выезжает сверху и исчезает через 3,5 с (клик закрывает сразу).
* Свой заголовок окна вместо системного (WindowChrome): перетаскивается верхняя полоса, края тянутся, работают Snap и двойной клик (развернуть). Справа вверху две кнопки в стиле Windows: «Свернуть» (в панель задач) и «Закрыть». «Закрыть» выполняет «Действие при закрытии» из настроек: спросить, свернуть в трей или закрыть лаунчер.
* Сообщения и подтверждения показываются в собственном диалоге: белая карточка, круглая иконка, кнопки справа внизу; окно под ним затемняется. Для опасных действий кнопка красная, а Enter выбирает «Отмена».

## Трей, одна копия и журнал

* **Кнопка «Закрыть»** вверху окна (а также Alt+F4 и «Закрыть окно» на панели задач) спрашивает: свернуть в трей или закрыть лаунчер. С галочкой «Запомнить выбор» вопрос больше не появляется; поменять поведение можно в настройках («Действие при закрытии»: Спрашивать / В трей / Закрыть).
* **В трее** лаунчер работает как обычно: следит за VPN и закрывает приложения. Значок есть всегда, пока лаунчер запущен. Без VPN значок бледнеет и получает красную точку, в подсказке — состояние VPN и сколько процессов под контролем. Двойной клик открывает окно, правый клик — обычное меню Windows «Открыть / Журнал событий / Закрыть лаунчер». «Закрыть лаунчер» при запущенных приложениях спрашивает и закрывает их.
* **Уведомления.** Пока окно скрыто или свёрнуто, уведомления лаунчера (обрыв VPN, закрытие приложений) показываются уведомлениями Windows. Если нужен ответ (например, какое-то приложение не удалось закрыть), окно показывается само.
* **Одна копия.** Повторный запуск не открывает вторую копию, а показывает окно уже работающей, даже из трея. После установки обновления новая версия ждёт до 15 с, пока закроется старая.
* **Журнал событий** (`%LOCALAPPDATA%\KillSwitchLauncher\events.log`, последние 500 записей): запуск и закрытие лаунчера, подключение и обрыв VPN, запуски, закрытия Kill-Switch, неудачи, заблокированные перезапуски, изменения Kill-Switch и правил, обновления. Открывается из настроек («Журнал») и из меню трея. В окне: «Открыть файл» (в текстовом редакторе) и «Очистить».
* **Обновление при запуске.** Лаунчер проверяет обновления сам, без уведомления: если есть новая версия, на кнопке «Настройки» появляется кружок с цифрой 1, а панель настроек при открытии сразу прокручивается к строке обновления.

## Где хранятся данные

`%LOCALAPPDATA%\KillSwitchLauncher\settings.json`: список приложений, состояние Kill-Switch, режим правила VPN, выбранные адаптеры, все адаптеры, которые лаунчер видел (для списка «удалённых»), и действие при закрытии окна.
`%LOCALAPPDATA%\KillSwitchLauncher\events.log`: журнал событий.
Файл пишется атомарно (временный файл, затем замена). Если файл повреждён, лаунчер сохраняет его копию как `settings.json.broken` и стартует с чистыми настройками.

## Как извлекается путь из ярлыка .lnk

`Services/ShortcutResolver.cs`:

1. Создаётся системный COM-объект **ShellLink** (CLSID `00021401-0000-0000-C000-000000000046`), тот же, которым пользуется Проводник. Ссылка на Windows Script Host (`IWshRuntimeLibrary`) не нужна.
2. Через его интерфейс `IPersistFile.Load()` загружается файл ярлыка.
3. `IShellLinkW.Resolve()` с флагами `SLR_NO_UI | SLR_NOUPDATE | SLR_NOSEARCH` и таймаутом 1 с: если цель перемещали, Windows попробует найти её, не показывая диалогов и не перезаписывая сам ярлык.
4. `GetPath()`, `GetArguments()`, `GetWorkingDirectory()` возвращают путь, аргументы и рабочую папку; переменные окружения (`%ProgramFiles%` и т.п.) раскрываются.
5. «Объявленный» (advertised) ярлык установщика MSI указывает не на файл, а на компонент продукта: путь к `.exe` берётся через `MsiGetShortcutTarget` и `MsiGetComponentPath`.
6. Ярлык приложения Microsoft Store пути к файлу не имеет: внутри него элемент папки «Приложения» (`shell:AppsFolder`). Из него берётся AppUserModelId вида `Publisher.App_8wekyb3d8bbwe!App`.

В диалоге выбора файла выставлено `DereferenceLinks = false`, иначе Windows сама подменила бы ярлык на цель и аргументы ярлыка потерялись бы.

**Лаунчер хранит сам ярлык.** При каждом запуске с плитки ярлык читается заново, поэтому если программа обновилась и ярлык теперь ведёт в другое место, лаунчер запустит то, на что ярлык указывает сейчас. Путь, аргументы и рабочая папка с прошлого запуска сохраняются в `settings.json` как запасной вариант на случай, если ярлык удалят.

**Приложения Microsoft Store** запускаются через `IApplicationActivationManager.ActivateApplication`: их процесс создаёт сама Windows и сообщает его PID. Поэтому создать такой процесс сразу внутри задания нельзя. Лаунчер забирает его в задание сразу после старта, а процессы, которые приложение успело породить за это мгновение, подбирает по папке приложения в `C:\Program Files\WindowsApps`. Иконка берётся с ярлыка так, как её рисует Проводник.

## Как отслеживается VPN

`Services/VpnAdapterDetector.cs` и `Services/VpnMonitor.cs`.

**Какой адаптер считается VPN.** В Windows нет признака «это VPN», поэтому используется эвристика по `NetworkInterface.GetAllNetworkInterfaces()`:

* тип `Ppp` (встроенный VPN Windows: PPTP, L2TP, SSTP, IKEv2) или `Tunnel`;
* либо ключевые слова в имени/описании: VPN, WireGuard, Wintun, TAP, TUN, OpenVPN, Cisco AnyConnect, Fortinet, GlobalProtect, Pulse/Ivanti, Check Point, SonicWall и др.;
* исключаются служебные псевдо-туннели Windows (Teredo, ISATAP, 6to4, IP-HTTPS), loopback и WAN Miniport;
* адаптер «активен», если `OperationalStatus == Up` **и** у него уже есть рабочий IP-адрес (не 169.254.x.x и не IPv6 link-local). TAP и Wintun бывают в состоянии Up до того, как туннель реально поднялся;
* в списке правил адаптер показывается по продукту, определённому по драйверу («OpenVPN (TAP)», «OpenVPN (DCO)», «WireGuard» и т.д.), а ниже мелко его системное имя и драйвер.

> **OpenVPN и «Подключение по локальной сети».** Классический OpenVPN работает через драйвер «TAP-Windows Adapter V9», а Windows по умолчанию называет этот адаптер «Подключение по локальной сети» / «Ethernet N». Это не обычная сетевая карта, а именно туннель OpenVPN. Новые версии OpenVPN 2.6+ могут использовать вместо него драйвер «OpenVPN Data Channel Offload».

**Когда проверяется.** Сразу по событиям Windows `NetworkChange.NetworkAddressChanged` и `NetworkAvailabilityChanged` (приходят при подъёме/падении туннеля) и дополнительно каждые 2 секунды по таймеру, на случай если VPN-клиент меняет состояние адаптера без смены адресов. Перед каждым запуском приложения статус проверяется заново, а не берётся из кэша.

**Правила для нескольких VPN** (кнопка «Настройки», раздел «Когда VPN считается подключённым»):

| Режим | VPN считается подключённым, когда |
|---|---|
| «Любой VPN» (по умолчанию) | активен любой адаптер, похожий на VPN |
| «Один из» | активен хотя бы один из отмеченных адаптеров |
| «Все» | активны все отмеченные адаптеры |

Адаптеры запоминаются по имени (`NetworkInterface.Name`, например имя подключения или туннеля WireGuard). В режимах «Один из» и «Все» без отмеченных адаптеров VPN считается отключённым (безопасное значение по умолчанию), а в панели правил появляется предупреждение. При переключении в эти режимы с пустым выбором лаунчер сам включает адаптеры VPN, активные в этот момент, чтобы смена режима не «уронила» статус и не сработал Kill-Switch.

**Кнопка «Применить».** Переключатели в «Настройках» (Kill-Switch, режим, выбор адаптеров) меняют только черновик. В силу и в `settings.json` изменения попадают по кнопке «Применить»; «Отменить» или закрытие панели без применения возвращают всё как было. Защита от случайных кликов.

**«Показывать все адаптеры»** стоит над списком адаптеров. Это только фильтр списка: действует сразу, не требует «Применить» и при каждом запуске выключен. Остальные адаптеры появляются под VPN отдельной группой «Другие адаптеры», а сам список VPN при этом не перестраивается. Списки обновляются на месте, поэтому переключатели не перерисовываются и не дёргаются.

Настройки выезжают справа на всю высоту окна поверх шапки, фон под ними размывается. Панель закрывается крестиком или кликом мимо неё; неприменённые изменения при этом отменяются.

**Удалённые адаптеры.** Некоторые VPN (например, WireGuard) создают адаптер при подключении и удаляют при отключении. Лаунчер запоминает каждый адаптер, который хоть раз попал в список: монитор присылает снимок при любом изменении набора адаптеров, поэтому ловятся и короткоживущие. Адаптеры, которых сейчас нет в системе, собраны внизу в отдельной свёрнутой группе «Удалённые адаптеры». Их можно отмечать в правилах, как обычные, и «забыть» кнопкой с корзиной; если такой адаптер появится снова, лаунчер запомнит его заново.

## Kill-Switch

**Почему недостаточно запомнить PID.** Ярлык Discord запускает не сам Discord, а `Update.exe --processStart Discord.exe`. Update.exe стартует Discord.exe и сразу завершается. Если помнить только PID Update.exe, через мгновение кажется, что ничего не запущено. `Process.Kill(entireProcessTree: true)` тоже не помогал: он ищет потомков по живым родителям, а у осиротевшего Discord.exe родителя уже нет. Так же ведут себя Slack, Teams classic и другие программы на Squirrel, а ещё любые программы, которые уже были открыты: новая копия передаёт управление старой и выходит.

**Как устроено:**

* **Задание Windows (Job Object).** Программа создаётся приостановленной, помещается в отдельное задание и только потом запускается. Всё, что она породит дальше (обновление, перезапуск, вспомогательные процессы), автоматически оказывается в том же задании, даже если родитель уже завершился. При обрыве VPN задание закрывается целиком одним вызовом `TerminateJobObject`; перед этим заданию запрещается создавать новые процессы, чтобы ничего не родилось в момент закрытия.
* **Подхват уже запущенного приложения.** При запуске и потом раз в секунду лаунчер ищет процессы с тем же `.exe` из папки приложения, которые работают вне задания (например, Discord из автозагрузки), и переносит их в задание. Для Squirrel-программ папкой считается общая `...\Discord`, а не `app-1.0.x`, а имя берётся и из `--processStart`. Если программа лежит прямо в общей папке (Program Files, System32, «Загрузки») или это общий «движок» (java, python, cmd), подхвата нет: под контролем только то, что запустил сам лаунчер. Чужие сеансы на терминальном сервере не трогаются.
* **Блокировка повторного запуска.** После срабатывания Kill-Switch процессы закрытого приложения, которые появятся снова, закрываются сразу, пока VPN не вернётся или Kill-Switch не выключат. Об этом сообщает уведомление «Запуск без VPN заблокирован».
* **Закрытие вместе с лаунчером.** Пока Kill-Switch включён, у заданий стоит флаг «закрыть процессы при закрытии задания». Если лаунчер аварийно завершится или его снимут в диспетчере задач, Windows сама закроет приложения, а не оставит их работать без защиты. При выключенном Kill-Switch флага нет, и приложения переживают лаунчер.
* **Обновления Squirrel.** Если в лаунчер добавлен сам `...\app-1.0.9\Discord.exe`, а после обновления папка сменилась, лаунчер находит новую версию и запоминает путь.
* На плитке видно, сколько процессов приложения под контролем (у Discord их обычно 5–7).

Кроме того:

* Kill-Switch срабатывает в фоновом потоке монитора, не дожидаясь интерфейса. После этого показывается список закрытых программ и тех, что закрыть не удалось.
* Гонка «VPN упал между проверкой и стартом» закрыта: сразу после старта статус проверяется ещё раз.
* Изменение правила, из-за которого VPN перестал считаться подключённым, тоже срабатывает как обрыв.
* Опция находится в «Настройках» (раздел «Защита») и сохраняется. Выключение требует подтверждения и кнопки «Применить», а пока Kill-Switch выключен, на главном экране висит красная метка «Kill-Switch выключен».
* При закрытии окна с включённым Kill-Switch лаунчер предупреждает и завершает запущенные им программы.

## Ограничения

* Всё, что приложение запустило само, считается его частью. Если из Discord открыть ссылку, а браузер в этот момент не был запущен, браузер окажется в задании Discord и закроется вместе с ним. Если браузер уже был открыт, ссылка уйдёт в него и он не пострадает.
* Программу, которой нужны права администратора, лаунчер без прав администратора поместить в задание и закрыть, скорее всего, не сможет: при первом запуске он об этом предупредит, а при обрыве VPN покажет её в списке «не удалось закрыть». Для таких программ запускайте лаунчер от имени администратора.
* Подхват работает раз в секунду, поэтому процесс, запущенный в обход лаунчера, может проработать до секунды.
* Определение VPN эвристическое. Для надёжности в строгом режиме лучше явно отметить нужные адаптеры в правилах.

## Обновления

Лаунчер обновляется из релизов GitHub: <https://github.com/psibia/safe-launcher/releases>.

* **При запуске** лаунчер тихо проверяет релизы. Если есть версия новее, на кнопке «Настройки» появляется кружок с цифрой 1, а строка обновления в настройках подсвечивается; если GitHub недоступен, ничего не показывается.
* **В настройках** внизу есть строка «О программе»: текущая версия, состояние и две кнопки. «Проверить» проверяет вручную и превращается в «Обновить», когда найдено обновление. «Что нового» открывает описание изменений в небольшом окне: если обновление есть, то для новой версии (с кнопкой «Обновить»), иначе для установленной.
* **Обновление.** Установщик скачивается с лоадером (прогресс, размер, «Отмена»), проверяются размер и SHA-256 (GitHub указывает её у файлов релиза). Затем установщик запускается в тихом режиме в ту же папку и для тех же пользователей, а лаунчер закрывается. Если Kill-Switch включён и приложения запущены, лаунчер сначала спросит, закрывать ли их. После установки новая версия запускается сама и показывает уведомление «Обновление установлено» или «Не удалось обновить».

**Как выкладывать релиз:**

1. Поднимите `<Version>` в `KillSwitchLauncher.csproj` и соберите установщик (`installer\build-installer.cmd`).
2. На GitHub создайте релиз с тегом `v1.0.0` (или `1.0.0`), версия в теге должна совпадать с `<Version>`.
3. Приложите к релизу `installer\Output\SafeLauncher-Setup-1.0.0.exe`. Лаунчер берёт первый `.exe`, в имени которого есть `Setup`.
4. Описание изменений пишите в описании релиза, Markdown поддерживается: заголовки, списки, **жирный**, `код`. Ссылки показываются текстом.

Черновики и пре-релизы лаунчер не видит. Репозиторий должен быть публичным: лаунчер обращается к GitHub без входа в аккаунт (лимит GitHub для этого — 60 запросов в час с одного IP).

## Установщик для коллег

В папке `installer` лежат скрипт Inno Setup (`KillSwitchLauncher.iss`) и `build-installer.cmd`.

1. Один раз установите [Inno Setup 6](https://jrsoftware.org/isdl.php).
2. Запустите `installer\build-installer.cmd`. Он публикует приложение в `installer\publish` (Release, win-x64, self-contained, один exe), затем собирает установщик.
3. Готовый файл: `installer\Output\SafeLauncher-Setup-<версия>.exe`. Его и отправляйте коллегам.

Что делает установщик: по умолчанию ставит лаунчер только для текущего пользователя без прав администратора (можно выбрать «для всех пользователей»), создаёт ярлык в меню «Пуск» и по желанию на рабочем столе, предлагает запустить лаунчер. .NET 8 на ПК не нужен, он встроен в exe. Повторный запуск установщика новой версии обновляет установленную; настройки пользователя при удалении сохраняются. Версия берётся из `<Version>` в `KillSwitchLauncher.csproj`.

Windows SmartScreen может предупреждать о неизвестном издателе, потому что установщик не подписан: «Подробнее» → «Выполнить в любом случае».
