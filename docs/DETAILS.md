# Безопасный лаунчер: подробное описание

Краткое описание проекта в [README](../README.md). Здесь подробности для разработчиков.

WPF-лаунчер (.NET 8) для корпоративных утилит, которые должны работать только внутри VPN.
Запускает программы только при активном VPN, запоминает их процессы и, если VPN пропадает,
принудительно их завершает (опция «Kill-Switch»).

## Сборка и запуск

Нужен .NET 8 SDK для Windows (или Visual Studio 2022 17.8+ с нагрузкой «Разработка классических приложений .NET»).

```powershell
git clone https://github.com/psibia/safe-launcher.git
cd safe-launcher
dotnet run --project KillSwitchLauncher
# или самодостаточный exe:
dotnet publish KillSwitchLauncher -c Release -r win-x64 --self-contained -p:PublishSingleFile=true
```

Либо откройте `KillSwitchLauncher.sln` в Visual Studio и нажмите F5.

Подключениям лаунчера нужна служба «Безопасный лаунчер — сеть» с ядром VPN в `C:\Program Files\SafeLauncher\core`.
При разработке ставьте и обновляйте их из исходников: закройте лаунчер и запустите `tools\update-service.cmd`.
Скрипт соберёт службу (и ядро, если установлено не той версии; для ядра нужны Git и Go) и спросит права администратора
только для копирования. Если служба старее лаунчера, при запуске приложения лаунчер скажет об этом.

Готовый установщик для Windows — в разделе [Releases](https://github.com/psibia/safe-launcher/releases).

## Тесты

В решении есть проект `KillSwitchLauncher.Tests` (xUnit). Запуск: Visual Studio → «Тест» → «Обозреватель тестов» → «Запустить все», или в консоли:

```powershell
dotnet test
```

Проверяются журнал событий, настройки (в том числе перенос настроек 1.x, сетевые условия приложений и шифрование ключей подключений), настройки ядра VPN, которые собирает служба, и обмен лаунчера со службой, разбор ссылок, подписок и файлов WireGuard и понятные причины неработающего подключения, запуск и выключение ядра вместе с приложениями, закрытие приложений при обрыве сервера или падении ядра, DNS приложений через их подключение, обновление подписок, обновления (разбор релизов, загрузка с проверкой SHA-256), правила VPN и распознавание адаптеров, блокировка трафика мимо VPN (набор фильтров для службы, повтор после сбоя службы, системный прокси, переменные прокси), одна копия лаунчера, Kill-Switch на настоящих процессах, журнал DNS (разбор доменов, журнал, фильтр по приложениям, обмен с помощником, раскладка структур Windows), логика главного окна (страницы, уход с несохранённым, мастер первого запуска, добавление приложения и его страница), распознавание вставленного подключения, программы из меню «Пуск», ярлыки и значок в трее. Тесты работают во временной папке и не трогают настройки лаунчера. Для проверки Kill-Switch сборка тестов сама служит маленькой программой-«приложением», поэтому настоящие программы не закрываются.

## Интерфейс

Стиль «мягкой панели»: светло-серый фон окна, большая внутренняя панель со скруглением, белые карточки с крупным радиусом и мягкими тенями, градиент голубой → фиолетовый как акцент, крупные жирные заголовки, кнопки-«таблетки».

* Всё содержимое стоит на одной сетке: шапка, заголовок, кнопки, плитки и карточка настроек начинаются и заканчиваются в 40 px от краёв окна. При наведении у плиток меняется только тень и подсветка круга под иконкой, сами плитки не двигаются.
* Шапка в одну строку. В ней сводка: «Защищены 2 из 3», «Ничего не запущено» с цветным кругом (зелёный — всё под защитой, жёлтый — приложения ждут сеть, красный — есть приложения без защиты). По клику — состояние системного VPN и каждого приложения. Если при подключении лаунчера включён ещё один VPN на весь компьютер, под шапкой появляется предупреждение.
* Плитки: иконка приложения в сером круге, название под ней (до двух строк). Кольцо вокруг иконки показывает состояние: зелёное — работает под защитой, жёлтое с меткой «ждёт сеть» — сервер не отвечает, серое с меткой «без защиты» — запущено мимо лаунчера или без VPN. Под названием — подключение приложения, если оно не общее. Подсказка с путём появляется под плиткой, не перекрывая иконку.
* Настройки и настройки приложения — отдельные страницы на всё окно: кнопка «← Приложения» вверху, Esc тоже возвращает. Разделы настроек: «Подключение», «Подключения лаунчера», «Адаптеры», «Защита», «Окно и трей», «Журнал событий», «О программе». «Применить» и «Отменить» появляются внизу, только когда что-то изменено; уход со страницы с неприменёнными изменениями спрашивает «Применить / Не сохранять / Остаться».
* Страница приложения (пункт «Настройки приложения» в меню плитки): название, условие запуска («Как в общих», «Свои адаптеры», «Своё подключение» с вкладками «Выбрать» и «Добавить подключение»), «Не запускать без VPN» и «Закрывать при обрыве» (как в общих, вкл или выкл), исключения, журнал DNS, параметры запуска.
* Добавить приложение: кнопкой или перетащив в окно .exe или ярлык. Для одной программы сразу открывается её страница, и она добавляется по «Добавить»; несколько программ добавляются сразу, «как в общих».
* «Добавить подключение» — одно поле: лаунчер сам понимает, ссылка это, адрес подписки или текст файла WireGuard, и показывает, что распознал. Подключение из буфера обмена подставляется само. Отдельная вкладка — прокси другой VPN-программы; если запущены v2rayN, Clash Verge, Hiddify или NekoRay, лаунчер предлагает их обычный порт.
* Мастер первого запуска (только при первой установке): подключение (или «У меня уже есть VPN-программа»), проверка (задержка, страна, IP) и программы из меню «Пуск» с галочками. Можно пропустить.
* Переключатели: «таблетка», во включённом состоянии с градиентом. Длинные подписи переносятся внутри строки и не залезают под переключатель.
* Меню по правому клику на плитке: своё оформление, название приложения в заголовке, иконки пунктов, красный пункт «Убрать из лаунчера».
* Подключение и обрыв VPN, запуск и добавление приложений сопровождаются уведомлением-«таблеткой» с цветным кругом. Оно выезжает сверху и исчезает через 3,5 с (клик закрывает сразу).
* Свой заголовок окна вместо системного (WindowChrome): перетаскивается верхняя полоса, края тянутся, работают Snap и двойной клик (развернуть). Справа вверху две кнопки в стиле Windows: «Свернуть» (в панель задач) и «Закрыть». «Закрыть» выполняет «Действие при закрытии» из настроек: спросить, свернуть в трей или закрыть лаунчер.
* Сообщения и подтверждения показываются в собственном диалоге: белая карточка, круглая иконка, кнопки справа внизу; окно под ним затемняется. Для опасных действий кнопка красная, а Enter выбирает «Отмена».

## Трей, одна копия и журнал

* **Кнопка «Закрыть»** вверху окна (а также Alt+F4 и «Закрыть окно» на панели задач) спрашивает: свернуть в трей или закрыть лаунчер. С галочкой «Запомнить выбор» вопрос больше не появляется; поменять поведение можно в настройках («Действие при закрытии»: Спрашивать / В трей / Закрыть).
* **В трее** лаунчер работает как обычно: следит за VPN и закрывает приложения. Значок есть всегда, пока лаунчер запущен. Когда есть приложения без защиты или ждущие сеть (или нужен системный VPN, а он выключен), значок бледнеет и получает красную точку, в подсказке — сводка из шапки. Двойной клик открывает окно, правый клик — обычное меню Windows: «Открыть», «Завершить» для каждого запущенного приложения, «Настройки», «Журнал событий», «Закрыть лаунчер». «Закрыть лаунчер» при запущенных приложениях спрашивает и закрывает их.
* **Уведомления.** Пока окно скрыто или свёрнуто, уведомления лаунчера (обрыв VPN, закрытие приложений) показываются уведомлениями Windows. Если нужен ответ (например, какое-то приложение не удалось закрыть), окно показывается само.
* **Одна копия.** Повторный запуск не открывает вторую копию, а показывает окно уже работающей, даже из трея. После установки обновления новая версия ждёт до 15 с, пока закроется старая.
* **Журнал событий** (`%LOCALAPPDATA%\KillSwitchLauncher\events.log`, последние 500 записей): запуск и закрытие лаунчера, подключение и обрыв VPN, запуски, закрытия Kill-Switch, неудачи, заблокированные перезапуски, изменения Kill-Switch и правил, обновления. Открывается из настроек (раздел «Журнал событий») и из меню трея. В окне: «Открыть файл» (в текстовом редакторе) и «Очистить».
* **Обновление при запуске.** Лаунчер проверяет обновления сам, без уведомления: если есть новая версия, на кнопке «Настройки» появляется кружок с цифрой 1, а настройки при открытии сразу показывают раздел «О программе».

## Где хранятся данные

`%LOCALAPPDATA%\KillSwitchLauncher\settings.json`: список приложений, состояние Kill-Switch, режим правила VPN, выбранные адаптеры, все адаптеры, которые лаунчер видел (для списка «удалённых»), и действие при закрытии окна. У каждого приложения хранится, включён ли для него журнал DNS (сами записи журнала на диск не пишутся), и его сетевые настройки: условие запуска («Как в общих», свои адаптеры или своё подключение), своя защита и домены-исключения. Там же список подключений лаунчера; ссылки, адреса подписок и конфигурации WireGuard в файле зашифрованы средствами Windows (DPAPI, значение вида `dpapi:…`): расшифровать их может только тот же пользователь на том же компьютере. Если перенести файл на другой компьютер, остальные настройки сохранятся, а ключи подключений придётся добавить заново.
`%LOCALAPPDATA%\KillSwitchLauncher\events.log`: журнал событий.
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, значение `SafeLauncher`: только если включено «Запускать вместе с Windows» (раздел «Окно и трей»). Лаунчер, запущенный так, сразу уходит в трей.
Файл пишется атомарно (временный файл, затем замена). Если файл повреждён, лаунчер сохраняет его копию как `settings.json.broken` и стартует с чистыми настройками. Файл от лаунчера 1.x при первом запуске версии 2.0 копируется в `settings.json.v0.bak` и переводится в новый формат: у всех приложений «Как в общих», в общих — прежнее правило адаптеров, поэтому всё работает как раньше.

## Как извлекается путь из ярлыка .lnk

`Services/ShortcutResolver.cs`:

1. Создаётся системный COM-объект **ShellLink** (CLSID `00021401-0000-0000-C000-000000000046`), тот же, которым пользуется Проводник. Ссылка на Windows Script Host (`IWshRuntimeLibrary`) не нужна.
2. Через его интерфейс `IPersistFile.Load()` загружается файл ярлыка.
3. `IShellLinkW.Resolve()` с флагами `SLR_NO_UI | SLR_NOUPDATE | SLR_NOSEARCH` и таймаутом 1 с: если цель перемещали, Windows попробует найти её, не показывая диалогов и не перезаписывая сам ярлык.
4. `GetPath()`, `GetArguments()`, `GetWorkingDirectory()` возвращают путь, аргументы и рабочую папку; переменные окружения (`%ProgramFiles%` и т.п.) раскрываются.
5. «Объявленный» (advertised) ярлык установщика MSI указывает не на файл, а на компонент продукта: путь к `.exe` берётся через `MsiGetShortcutTarget` и `MsiGetComponentPath`.
6. Ярлык приложения Microsoft Store пути к файлу не имеет: внутри него элемент папки «Приложения» (`shell:AppsFolder`). Из него берётся AppUserModelId вида `Publisher.App_8wekyb3d8bbwe!App`.

В диалоге выбора файла выставлено `DereferenceLinks = false`, иначе Windows сама подменила бы ярлык на цель и аргументы ярлыка потерялись бы.

**Лаунчер хранит сам ярлык.** При каждом запуске с плитки ярлык читается заново, поэтому если программа обновилась и ярлык теперь ведёт в другое место, лаунчер запустит то, на что ярлык указывает сейчас. Путь, аргументы и рабочая папка с прошлого запуска сохраняются в `settings.json` как запасной вариант на случай, если ярлык удалят.

**Приложения Microsoft Store** запускаются через `IApplicationActivationManager.ActivateApplication`: их процесс создаёт сама Windows и сообщает его PID. Поэтому создать такой процесс сразу внутри задания нельзя. Лаунчер забирает его в задание сразу после старта, а процессы, которые приложение успело породить за это мгновение, подбирает по папке приложения в `C:\Program Files\WindowsApps`. Иконка берётся с ярлыка так, как её рисует Проводник.

## Как отслеживается VPN

`Services/VpnAdapterDetector.cs` и `Services/VpnMonitor.cs`.

**Какой адаптер считается VPN.** В Windows нет признака «это VPN», поэтому используется эвристика по `NetworkInterface.GetAllNetworkInterfaces()`:

* тип `Ppp` (встроенный VPN Windows: PPTP, L2TP, SSTP, IKEv2) или `Tunnel`;
* либо ключевые слова в имени/описании: VPN, WireGuard, Wintun, TAP, TUN, OpenVPN, Cisco AnyConnect, Fortinet, GlobalProtect, Pulse/Ivanti, Check Point, SonicWall и др.;
* исключаются служебные псевдо-туннели Windows (Teredo, ISATAP, 6to4, IP-HTTPS), loopback и WAN Miniport;
* адаптер «активен», если `OperationalStatus == Up` **и** у него уже есть рабочий IP-адрес (не 169.254.x.x и не IPv6 link-local). TAP и Wintun бывают в состоянии Up до того, как туннель реально поднялся;
* в списке правил адаптер показывается по продукту, определённому по драйверу («OpenVPN (TAP)», «OpenVPN (DCO)», «WireGuard» и т.д.), а ниже мелко его системное имя и драйвер.

> **OpenVPN и «Подключение по локальной сети».** Классический OpenVPN работает через драйвер «TAP-Windows Adapter V9», а Windows по умолчанию называет этот адаптер «Подключение по локальной сети» / «Ethernet N». Это не обычная сетевая карта, а именно туннель OpenVPN. Новые версии OpenVPN 2.6+ могут использовать вместо него драйвер «OpenVPN Data Channel Offload».

**Когда проверяется.** Сразу по событиям Windows `NetworkChange.NetworkAddressChanged` и `NetworkAvailabilityChanged` (приходят при подъёме/падении туннеля) и дополнительно каждые 2 секунды по таймеру, на случай если VPN-клиент меняет состояние адаптера без смены адресов. Перед каждым запуском приложения статус проверяется заново, а не берётся из кэша.

**Правила для нескольких VPN** (кнопка «Настройки», раздел «Когда VPN считается подключённым»):

| Режим | VPN считается подключённым, когда |
|---|---|
| «Любой VPN» (по умолчанию) | активен любой адаптер, похожий на VPN |
| «Один из» | активен хотя бы один из отмеченных адаптеров |
| «Все» | активны все отмеченные адаптеры |

Адаптеры запоминаются по имени (`NetworkInterface.Name`, например имя подключения или туннеля WireGuard). В режимах «Один из» и «Все» без отмеченных адаптеров VPN считается отключённым (безопасное значение по умолчанию), а в панели правил появляется предупреждение. При переключении в эти режимы с пустым выбором лаунчер сам включает адаптеры VPN, активные в этот момент, чтобы смена режима не «уронила» статус и не сработал Kill-Switch.

**Кнопка «Применить».** Переключатели в «Настройках» (Kill-Switch, режим, выбор адаптеров) меняют только черновик. В силу и в `settings.json` изменения попадают по кнопке «Применить»; «Отменить» или закрытие панели без применения возвращают всё как было. Защита от случайных кликов.

**«Показывать все адаптеры»** стоит над списком адаптеров. Это только фильтр списка: действует сразу, не требует «Применить» и при каждом запуске выключен. Остальные адаптеры появляются под VPN отдельной группой «Другие адаптеры», а сам список VPN при этом не перестраивается. Списки обновляются на месте, поэтому переключатели не перерисовываются и не дёргаются.

Настройки выезжают справа на всю высоту окна поверх шапки, фон под ними размывается. Панель закрывается крестиком или кликом мимо неё; неприменённые изменения при этом отменяются.

**Удалённые адаптеры.** Некоторые VPN (например, WireGuard) создают адаптер при подключении и удаляют при отключении. Лаунчер запоминает каждый адаптер, который хоть раз попал в список: монитор присылает снимок при любом изменении набора адаптеров, поэтому ловятся и короткоживущие. Адаптеры, которых сейчас нет в системе, собраны внизу в отдельной свёрнутой группе «Удалённые адаптеры». Их можно отмечать в правилах, как обычные, и «забыть» кнопкой с корзиной; если такой адаптер появится снова, лаунчер запомнит его заново.

## Kill-Switch

**Почему недостаточно запомнить PID.** Ярлык Discord запускает не сам Discord, а `Update.exe --processStart Discord.exe`. Update.exe стартует Discord.exe и сразу завершается. Если помнить только PID Update.exe, через мгновение кажется, что ничего не запущено. `Process.Kill(entireProcessTree: true)` тоже не помогал: он ищет потомков по живым родителям, а у осиротевшего Discord.exe родителя уже нет. Так же ведут себя Slack, Teams classic и другие программы на Squirrel, а ещё любые программы, которые уже были открыты: новая копия передаёт управление старой и выходит.

**Как устроено:**

* **Задание Windows (Job Object).** Программа создаётся приостановленной, помещается в отдельное задание и только потом запускается. Всё, что она породит дальше (обновление, перезапуск, вспомогательные процессы), автоматически оказывается в том же задании, даже если родитель уже завершился. При обрыве VPN задание закрывается целиком одним вызовом `TerminateJobObject`; перед этим заданию запрещается создавать новые процессы, чтобы ничего не родилось в момент закрытия.
* **Подхват уже запущенного приложения.** При запуске и потом раз в секунду лаунчер ищет процессы с тем же `.exe` из папки приложения, которые работают вне задания (например, Discord из автозагрузки), и переносит их в задание. Для Squirrel-программ папкой считается общая `...\Discord`, а не `app-1.0.x`, а имя берётся и из `--processStart`. Если программа лежит прямо в общей папке (Program Files, System32, «Загрузки») или это общий «движок» (java, python, cmd), подхвата нет: под контролем только то, что запустил сам лаунчер. Чужие сеансы на терминальном сервере не трогаются.
* **Блокировка повторного запуска.** После срабатывания Kill-Switch процессы закрытого приложения, которые появятся снова, закрываются сразу, пока VPN не вернётся или Kill-Switch не выключат. Об этом сообщает уведомление «Запуск без VPN заблокирован».
* **Закрытие вместе с лаунчером.** Пока Kill-Switch включён, у заданий стоит флаг «закрыть процессы при закрытии задания». Если лаунчер аварийно завершится или его снимут в диспетчере задач, Windows сама закроет приложения, а не оставит их работать без защиты. При выключенном Kill-Switch флага нет, и приложения переживают лаунчер.
* **Обновления Squirrel.** Если в лаунчер добавлен сам `...\app-1.0.9\Discord.exe`, а после обновления папка сменилась, лаунчер находит новую версию и запоминает путь.
* На плитке видно, сколько процессов приложения под контролем (у Discord их обычно 5–7).
* **«Завершить все процессы»** в меню плитки закрывает одно приложение так же, как Kill-Switch: задание целиком, процессы вне задания и найденные копии. Перед этим лаунчер спрашивает подтверждение, а запустить приложение снова можно сразу, без блокировки. Пункт активен, пока у приложения есть процессы под контролем.

Кроме того:

* Kill-Switch срабатывает в фоновом потоке монитора, не дожидаясь интерфейса. После этого показывается список закрытых программ и тех, что закрыть не удалось.
* Гонка «VPN упал между проверкой и стартом» закрыта: сразу после старта статус проверяется ещё раз.
* Изменение правила, из-за которого VPN перестал считаться подключённым, тоже срабатывает как обрыв.
* Опция находится в «Настройках» (раздел «Защита») и сохраняется. Выключение требует подтверждения и кнопки «Применить», а пока Kill-Switch выключен, на главном экране висит красная метка «Kill-Switch выключен».
* При закрытии окна с включённым Kill-Switch лаунчер предупреждает и завершает запущенные им программы.

## Журнал DNS

Показывает, к каким доменам обращается приложение, запущенное из лаунчера. Включается для каждого приложения отдельно: правый клик по плитке → «Включить журнал DNS». На плитке появляется значок «DNS», а в меню — «Открыть журнал DNS».

* **Окно журнала** не мешает работать с лаунчером и обновляется само. В строке: время, домен, тип записи (A, AAAA, HTTPS…) и процесс с PID. Переключатель «Только уникальные» показывает каждый домен один раз: сколько раз к нему обращались, какими типами и когда последний раз. Есть поиск. «Копировать» (и Ctrl+C) копирует только домены выделенных строк, по одному в строке, без времени и прочего. Национальные домены показываются буквами, а копируются как есть в DNS (`xn--…`).
* **Что попадает.** Только запросы процессов этого приложения: запущенного из лаунчера, его потомков и подхваченных копий. Чужие запросы сразу отбрасываются и нигде не хранятся. Повтор того же запроса тем же процессом в течение секунды считается одним. Новый запуск приложения, выключение и включение журнала отмечаются разделителем.
* **Хранение.** Только в памяти, последние 5000 записей на приложение (счётчики «уникальных» — за всё время). Журнал остаётся до закрытия лаунчера, даже если приложение закрыли или журнал выключили. Включён ли журнал, запоминается; запись начинается при запуске приложения из лаунчера или при включении журнала, а не при запуске самого лаунчера.
* **Права.** Запросы берутся из системного журнала событий Windows (ETW, провайдер Microsoft-Windows-DNS-Client), а для него нужны права администратора. Если лаунчер запущен от имени администратора или пользователь входит в группу «Пользователи журналов производительности» (Performance Log Users), запись идёт прямо в лаунчере. Иначе Windows один раз спросит разрешение (UAC) для помощника: это тот же `KillSwitchLauncher.exe` с ключом `--dns-collector`, без окон. Он только читает события DNS и передаёт их лаунчеру по именованному каналу, доступному лишь текущему пользователю; обе стороны проверяют, что на другом конце именно они. Когда журнал выключен у всех приложений или лаунчер закрыт (даже аварийно), помощник останавливается. Если отказать в UAC, журнал не включится, а приложение запустится как обычно.

Ограничения журнала:

* Видны только запросы через системный DNS-клиент Windows. Если программа обращается к DNS сама, минуя Windows (свой DNS-клиент, DNS over HTTPS внутри программы, как умеют браузеры), или подключается сразу по IP-адресу, таких обращений в журнале не будет.
* Процесс, который уже завершился, узнаётся ещё 10 секунд, чтобы не потерять запросы, пришедшие с опозданием.
* Журнал — инструмент наблюдения, а не защита: он ничего не блокирует.

## Безопасность сети

Главная задача лаунчера — контроль приложений, запущенных через него. Весь компьютер он не трогает: то, что действует шире, вынесено в отдельную настройку, по умолчанию выключенную, и перед её включением лаунчер объясняет, на что она повлияет.

**Через подключение лаунчера** (ядро VPN в службе):

* Трафик приложения ядро узнаёт по заданию Windows (метка процесса, см. [core/README.md](../core/README.md)) и отправляет через подключение приложения. Остальные программы идут как обычно, напрямую.
* DNS-запросы, которые приложение задаёт само (например, свой DNS-клиент браузера), ядро отправляет через подключение. Для файла WireGuard — на сервер из строки `DNS`, если он внутри туннеля.
* **«Блокировать трафик мимо VPN»** (раздел «Защита», по умолчанию включено). Служба ставит фильтры Windows (WFP) на программы приложения: в интернет — только через адаптер ядра. Программа, которая сама выбирает обычную сетевую карту (WebRTC в браузерах и мессенджерах, привязка к адресу), не соединится. Пока ядра нет, сети у приложения нет.
* Системный прокси Windows на этом же компьютере (его включают v2rayN, Clash и подобные программы) для таких приложений закрыт: иначе браузер отдал бы трафик другой VPN-программе. Лаунчер пишет об этом в журнал и показывает уведомление. Если подключение приложения — «прокси другой программы», системный прокси не закрывается.
* Переменные окружения `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY` (и строчные) у приложений, которым нужен VPN, убираются.

**С системным VPN** (ваша VPN-программа) маршрутом управляет она. С «Не запускать без VPN» и «Блокировать трафик мимо VPN» фильтры пускают приложение в интернет только через адаптеры VPN по правилу из раздела «Адаптеры». Если VPN отключился, сети у приложения нет, пока он не вернётся (или Kill-Switch закроет приложение).

**Как устроены фильтры.** Их ставит служба в динамическом сеансе WFP: когда лаунчер закрывается, служба их снимает, а если остановится сама, даже аварийно, их снимет Windows. Фильтры действуют, пока приложение запущено, на все его программы: exe самого приложения и каждого его процесса. Если фильтры не поставились (служба недоступна или устарела), приложение не запускается. Без лаунчера фильтров нет, поэтому приложения под блокировкой закрываются вместе с ним, в том числе при его сбое (перед обычным закрытием лаунчер спросит).

* Фильтр относится к файлу программы целиком. Та же программа, открытая не через лаунчер, пока приложение работает, тоже не сможет сама выбрать обычную сетевую карту: с системным VPN она выходит только через VPN, а с подключением лаунчера идёт через адаптер ядра, и ядро отправляет её напрямую, как остальные программы.
* Приложению закрыта домашняя сеть (принтеры, NAS). Внутри компьютера (127.0.0.1) сеть открыта.
* Программы Windows (`C:\Windows`), Защитника Windows и программы служб (даже остановленных) не ограничиваются: это затронуло бы весь компьютер. Лаунчер пишет об этом в журнал.

**«Скрывать DNS-запросы от провайдера»** (по умолчанию выключено, влияет на весь компьютер). В Windows DNS-запросы за все программы задаёт одна системная служба, поэтому без этой настройки провайдер может видеть имена сайтов, которые открывают приложения, хотя их трафик идёт через VPN.

* С подключением лаунчера ядро отвечает на DNS-запросы условными адресами 198.18.x.x (fakeip, время жизни 1 с) и узнаёт имя сайта при соединении: у приложений лаунчера имя уходит через подключение, у остальных программ адрес ищется как обычно. Служебные имена Windows (проверка сети, `.local`, обратные зоны, имена без точки) не подменяются.
* С системным VPN, пока работает приложение с «Не запускать без VPN», служба DNS Windows (она ищет имена за все программы) ходит на порт 53 только через адаптеры VPN со своим DNS-сервером. Если у VPN своего DNS-сервера нет, лаунчер DNS не ограничивает. Свои DNS-запросы приложений лаунчера тоже идут только через VPN. Другие программы, которые ищут адреса сами, не ограничиваются: так ядро VPN-программы находит свой сервер и переподключается.

**Когда приложения или лаунчер закрыты, всё как без VPN.** Ядро останавливается (через 10 с после последнего приложения), его адаптер исчезает, фильтры снимаются, кэш DNS Windows очищается. В системе остаётся только служба, которая без лаунчера ничего не делает.

Чего лаунчер не контролирует:

* запросы, которые за приложение делают Windows и её службы (обновления, фоновые загрузки BITS, открытие сетевых папок вида `\\адрес\папка`), и, без «Скрывать DNS-запросы», имена сайтов в DNS;
* прокси, указанный в настройках самой программы (например, в Telegram);
* процессы, которые программа запустила с правами администратора через окно UAC: они не попадают в задание лаунчера;
* программы Windows, которые запустило само приложение (например, cmd, PowerShell, curl): фильтр их не ограничивает. Обычно они идут тем же путём, что и приложение, но обойти VPN, сами выбрав сетевую карту, могут;
* программы с сетевого диска (`\\сервер\папка`): служба не может их проверить, поэтому с «Блокировать трафик мимо VPN» лаунчер их не запускает и предлагает скопировать программу на компьютер;
* если служба «Безопасный лаунчер — сеть» аварийно остановится, Windows снимет её фильтры. Служба перезапустится через несколько секунд, и лаунчер поставит фильтры снова, а пока покажет предупреждение. Приложения через подключение лаунчера при этом закрываются: ядро работает внутри службы;
* если одновременно работают ядро и приложение под системным VPN с блокировкой, трафик такого приложения может попасть в адаптер ядра, и тогда фильтр его не пропустит: приложение останется без сети, но мимо VPN не пойдёт.

## Ограничения

* Всё, что приложение запустило само, считается его частью. Если из Discord открыть ссылку, а браузер в этот момент не был запущен, браузер окажется в задании Discord и закроется вместе с ним. Если браузер уже был открыт, ссылка уйдёт в него и он не пострадает.
* Программу, которой нужны права администратора, лаунчер без прав администратора поместить в задание и закрыть, скорее всего, не сможет: при первом запуске он об этом предупредит, а при обрыве VPN покажет её в списке «не удалось закрыть». Для таких программ запускайте лаунчер от имени администратора.
* Подхват работает раз в секунду, поэтому процесс, запущенный в обход лаунчера, может проработать до секунды.
* Определение VPN эвристическое. Для надёжности в строгом режиме лучше явно отметить нужные адаптеры в правилах.

## Обновления

Лаунчер обновляется из релизов GitHub: <https://github.com/psibia/safe-launcher/releases>.

* **При запуске** лаунчер тихо проверяет релизы. Если есть версия новее, на кнопке «Настройки» появляется кружок с цифрой 1, а строка обновления в настройках подсвечивается; если GitHub недоступен, ничего не показывается.
* **В настройках** внизу есть строка «О программе»: текущая версия, состояние и две кнопки. «Проверить» проверяет вручную и превращается в «Обновить», когда найдено обновление. «Что нового» открывает описание изменений в небольшом окне: если обновление есть, то для новой версии (с кнопкой «Обновить»), иначе для установленной.
* **Обновление.** Установщик скачивается с лоадером (прогресс, размер, «Отмена»), проверяются размер и SHA-256 (GitHub указывает её у файлов релиза). Затем установщик запускается в тихом режиме в ту же папку и для тех же пользователей, а лаунчер закрывается. Если запущены приложения, которые без лаунчера остались бы без защиты, он сначала спросит, закрывать ли их. После установки новая версия запускается сама и показывает уведомление «Обновление установлено» или «Не удалось обновить».

**Как выкладывать релиз:**

1. Поднимите `<Version>` в `KillSwitchLauncher.csproj` и `SafeLauncher.Service.csproj` (одинаково) и соберите установщик (`installer\build-installer.cmd`).
2. На GitHub создайте релиз с тегом `v2.1.0` (или `2.1.0`), версия в теге должна совпадать с `<Version>`.
3. Приложите к релизу `installer\Output\SafeLauncher-Setup-2.1.0.0.exe`. Лаунчер берёт первый `.exe`, в имени которого есть `Setup`.
4. Описание изменений пишите в описании релиза, Markdown поддерживается: заголовки, списки, **жирный**, `код`. Ссылки показываются текстом.

Черновики и пре-релизы лаунчер не видит. Репозиторий должен быть публичным: лаунчер обращается к GitHub без входа в аккаунт (лимит GitHub для этого — 60 запросов в час с одного IP).

## Установщик

В папке `installer` лежат скрипт Inno Setup (`KillSwitchLauncher.iss`), `build-installer.cmd` и `prepare-core.ps1`.

1. Один раз установите [Inno Setup 6](https://jrsoftware.org/isdl.php) и .NET 8 SDK.
2. Запустите `installer\build-installer.cmd`. Он:
   * публикует лаунчер в `installer\publish` (Release, win-x64, self-contained, один exe);
   * публикует службу в `installer\publish-core` (тоже один exe со встроенным .NET) и кладёт рядом ядро `launcher-core.exe` нужной версии и файлы его лицензии. Ядро берётся готовым: `installer\launcher-core.exe`, уже установленное в `C:\Program Files\SafeLauncher\core`, `prototype\RouteCheck\bin\launcher-core.exe` или архив `launcher-core.zip` там же. Если подходящего нет, ядро собирается скриптом `core\build.ps1` (нужны Git и Go);
   * собирает установщик.
3. Готовый файл: `installer\Output\SafeLauncher-Setup-<версия>.exe`.

Что делает установщик:

* ставит лаунчер для всех пользователей в `C:\Program Files\Безопасный лаунчер` (нужны права администратора), а службу «Безопасный лаунчер — сеть» и ядро — в `C:\Program Files\SafeLauncher\core`. Служба запускается вместе с Windows и без лаунчера ничего не делает;
* создаёт ярлык в меню «Пуск» и по желанию на рабочем столе, предлагает запустить лаунчер (от имени обычного пользователя);
* перед заменой файлов ждёт, пока закроется лаунчер, и останавливает службу, а после установки регистрирует службу заново;
* при обновлении с версии 1.x, установленной «только для меня» (в AppData), удаляет ту копию; настройки сохраняются;
* при удалении останавливает и удаляет службу и убирает автозапуск лаунчера. Настройки пользователя (`%LOCALAPPDATA%\KillSwitchLauncher`) остаются.

.NET 8 на компьютере не нужен. Версия берётся из `<Version>` в `KillSwitchLauncher.csproj`.

Windows SmartScreen может предупреждать о неизвестном издателе, потому что установщик не подписан: «Подробнее» → «Выполнить в любом случае».
