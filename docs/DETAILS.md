# Безопасный лаунчер: подробное описание

Краткое описание проекта в [README](../README.md). Здесь подробности для разработчиков.

WPF-лаунчер (.NET 8) для корпоративных утилит, которые должны работать только внутри VPN.
Запускает программы только при активном VPN, запоминает их процессы и, если VPN пропадает,
принудительно их завершает (опция «Kill-Switch»).

## Сборка и запуск

Нужен .NET 8 SDK для Windows (или Visual Studio 2022 17.8+ с нагрузкой «Разработка классических приложений .NET»).

```powershell
git clone https://github.com/psibia/safe-launcher.git
cd safe-launcher
dotnet run --project KillSwitchLauncher
# или самодостаточный exe:
dotnet publish KillSwitchLauncher -c Release -r win-x64 --self-contained -p:PublishSingleFile=true
```

Либо откройте `KillSwitchLauncher.sln` в Visual Studio и нажмите F5.

Подключениям лаунчера нужна служба «Безопасный лаунчер — сеть» с ядром VPN в `C:\Program Files\SafeLauncher\core`.
При разработке ставьте и обновляйте их из исходников: закройте лаунчер и запустите `tools\update-service.cmd`.
Скрипт соберёт службу (и ядро, если установлено не той версии; для ядра нужны Git и Go) и спросит права администратора
только для копирования. Если служба старее лаунчера, при запуске приложения лаунчер скажет об этом.

Готовый установщик для Windows — в разделе [Releases](https://github.com/psibia/safe-launcher/releases).

## Тесты

В решении есть проект `KillSwitchLauncher.Tests` (xUnit). Запуск: Visual Studio → «Тест» → «Обозреватель тестов» → «Запустить все», или в консоли:

```powershell
dotnet test
```

Проверяются журнал событий, настройки (в том числе перенос настроек 1.x, сетевые условия приложений и шифрование ключей подключений), настройки ядра VPN, которые собирает служба, и обмен лаунчера со службой, разбор ссылок, подписок, файлов WireGuard и AmneziaWG, ключей vpn:// AmneziaVPN и понятные причины неработающего подключения, запуск и выключение ядра вместе с приложениями, закрытие приложений при обрыве сервера или падении ядра, DNS приложений через их подключение, обновление подписок, обновления (разбор релизов, загрузка с проверкой SHA-256), перевод настроек с системного VPN на основное подключение, распознавание адаптеров VPN, блокировка трафика мимо VPN (набор фильтров для службы, повтор после сбоя службы, системный прокси, переменные прокси), одна копия лаунчера, Kill-Switch на настоящих процессах, журнал DNS (разбор доменов, журнал, фильтр по приложениям, обмен с помощником, раскладка структур Windows), логика главного окна (страницы, уход с несохранённым, мастер первого запуска, добавление приложения и его страница), распознавание вставленного подключения, программы из меню «Пуск» и поиск по ним, ярлыки и значок в трее. Тесты работают во временной папке и не трогают настройки лаунчера. Для проверки Kill-Switch сборка тестов сама служит маленькой программой-«приложением», поэтому настоящие программы не закрываются.

## Интерфейс

Стиль «мягкой панели»: светло-серый фон окна, большая внутренняя панель со скруглением, белые карточки с крупным радиусом и мягкими тенями, градиент голубой → фиолетовый как акцент, крупные жирные заголовки, кнопки-«таблетки».

* Всё содержимое стоит на одной сетке: шапка, заголовок, кнопки, плитки и карточка настроек начинаются и заканчиваются в 40 px от краёв окна. При наведении у плиток меняется только тень и подсветка круга под иконкой, сами плитки не двигаются.
* Шапка в одну строку. В ней сводка: «Защищены 2 из 3», «Ничего не запущено» с цветным кругом (зелёный — всё под защитой, жёлтый — приложения ждут сеть, красный — есть приложения без защиты). По клику — состояние каждого приложения. Пока выключена «Защита от утечки DNS», под названием лаунчера вместо подписи висит красная метка «Возможна утечка DNS»; клик по ней открывает настройки, раздел «Защита». Если при подключении лаунчера включён ещё один VPN на весь компьютер, под шапкой появляется предупреждение.
* Плитки: иконка приложения в сером круге, название под ней (до двух строк). Кольцо вокруг иконки показывает состояние: зелёное — работает под защитой, жёлтое с меткой «ждёт сеть» — сервер подключения не отвечает (сети у приложения в это время нет), серое с меткой «без защиты» — запущено мимо лаунчера. Под названием — подключение приложения, если оно не основное, или «Без сети». Подсказка с путём появляется под плиткой, не перекрывая иконку.
* Настройки и настройки приложения — отдельные страницы на всё окно: кнопка «← Приложения» вверху, Esc тоже возвращает. Разделы настроек: «Подключения», «Защита», «Исключения», «Окно и трей», «Журналы», «Обновления». В «Подключениях» одно из подключений основное: через него идут приложения, у которых не выбрано своё. Первое добавленное подключение становится основным само, другое делает основным кнопка «Сделать основным» в его строке, и это действует сразу. «Применить» и «Отменить» появляются внизу, только когда что-то изменено в остальных разделах; уход со страницы с неприменёнными изменениями спрашивает «Применить / Не сохранять / Остаться».
* Страница приложения (пункт «Настройки приложения» в меню плитки): название, условие запуска («Основное подключение», «Своё подключение» с вкладками «Выбрать» и «Добавить подключение», «Без сети»), «Если открыто не из лаунчера» (как в общих, через лаунчер, через VPN, без интернета или напрямую; «Через лаунчер» для любого приложения, остальные варианты только для приложения через подключение лаунчера), «Закрывать при обрыве» (как в общих, вкл или выкл), исключения с выбором «Дополнять общие» или «Вместо общих» (защита и исключения скрыты при «Без сети»). Журнал DNS включается в меню плитки (см. «Журнал DNS»), параметры запуска берутся из ярлыка.
* «Добавить приложение» открывает страницу с программами из меню «Пуск» и галочками, как в мастере первого запуска. Над списком есть поиск по названию программы и имени её .exe: регистр не важен, «ё» и «е» не различаются, запрос в другой раскладке («ыеуфь») тоже находит программу, Esc очищает поле. Поиск только скрывает строки, отмеченные раньше программы остаются отмеченными. Уже добавленные отмечены серым и недоступны: убрать их можно только пунктом «Убрать из лаунчера» в меню плитки. Отмеченные добавляются кнопкой «Добавить» и идут через основное подключение; уход со страницы с отмеченными спрашивает, добавить ли их. «Выбрать в проводнике» добавляет одну программу (.exe или ярлык): сразу открывается её страница, и программа добавляется по «Добавить». Можно и перетащить в окно .exe или ярлык: для одной программы открывается её страница, несколько добавляются сразу.
* Одну программу (тот же exe-файл или то же приложение Microsoft Store) можно добавить только один раз, даже с другими параметрами запуска: ядро и фильтры Windows узнают приложение по программе, и копия, открытая по ярлыку, пошла бы через подключение одного из них наугад. Лаунчер скажет, под каким названием программа уже есть. Добавленные так до версии 2.3.1 не удаляются: при каждом запуске лаунчер напоминает о них в журнале событий и уведомлении.
* «Добавить подключение» — одно поле: лаунчер сам понимает, ссылка это, адрес подписки, текст файла WireGuard или AmneziaWG или ключ vpn:// программы AmneziaVPN, и показывает, что распознал. Из ключа от своего сервера (в AmneziaVPN «Поделиться», протокол AmneziaWG или WireGuard, формат «Для приложения AmneziaVPN») лаунчер берёт текст файла, который в ключе записан, и подставляет в него DNS из ключа и MTU 1376, как делает AmneziaVPN для Windows; дальше это обычное подключение AmneziaWG или WireGuard. Ключи сервиса Amnezia (Premium и Free) настроек не содержат: такой ключ лаунчер не примет и объяснит почему. Подключение из буфера обмена подставляется само. Подключение, которое уже есть, второй раз не добавляется, и лаунчер скажет, под каким названием оно есть: та же ссылка (даже с другим названием после «#»), тот же адрес подписки, файл WireGuard или ключ vpn://, тот же прокси. Отдельная вкладка — прокси другой VPN-программы; если запущены v2rayN, Clash Verge, Hiddify или NekoRay, лаунчер предлагает их обычный порт.
* Мастер первого запуска (только при первой установке): подключение, проверка (задержка, страна, IP) и программы из меню «Пуск» с галочками и поиском, как на странице «Добавить приложения». Можно пропустить.
* Переключатели: «таблетка», во включённом состоянии с градиентом. Длинные подписи переносятся внутри строки и не залезают под переключатель.
* Меню по правому клику на плитке: своё оформление, название приложения в заголовке, иконки пунктов, красный пункт «Убрать из лаунчера».
* «Убрать из лаунчера» у запущенного приложения его не закрывает: лаунчер предупреждает, что оно продолжит работать как обычная программа, и отпускает его. Дальше оно идёт напрямую, без фильтров и Kill-Switch, и не закроется вместе с лаунчером. Его копии, открытые по ярлыку, тоже сразу идут напрямую.
* Подключение и обрыв VPN, запуск и добавление приложений сопровождаются уведомлением-«таблеткой» с цветным кругом. Оно выезжает сверху и исчезает через 3,5 с (клик закрывает сразу).
* Свой заголовок окна вместо системного (WindowChrome): перетаскивается верхняя полоса, края тянутся, работают Snap и двойной клик (развернуть). Справа вверху две кнопки в стиле Windows: «Свернуть» (в панель задач) и «Закрыть». «Закрыть» выполняет «Действие при закрытии» из настроек: спросить, свернуть в трей или закрыть лаунчер.
* Сообщения и подтверждения показываются в собственном диалоге: белая карточка, круглая иконка, кнопки справа внизу; окно под ним затемняется. Для опасных действий кнопка красная, а Enter выбирает «Отмена».

## Трей, одна копия и журнал

* **Кнопка «Закрыть»** вверху окна (а также Alt+F4 и «Закрыть окно» на панели задач) спрашивает: свернуть в трей или закрыть лаунчер. С галочкой «Запомнить выбор» вопрос больше не появляется; поменять поведение можно в настройках («Действие при закрытии»: Спрашивать / В трей / Закрыть).
* **В трее** лаунчер работает как обычно: следит за VPN и закрывает приложения. Значок есть всегда, пока лаунчер запущен. Когда есть приложения без защиты или ждущие сеть, значок бледнеет и получает красную точку, в подсказке — сводка из шапки. Двойной клик открывает окно, правый клик — обычное меню Windows: «Открыть», «Завершить» для каждого запущенного приложения, «Настройки», «Закрыть лаунчер». «Закрыть лаунчер» при запущенных приложениях спрашивает и закрывает их.
* **Уведомления.** Пока окно скрыто или свёрнуто, уведомления лаунчера (обрыв VPN, закрытие приложений) показываются уведомлениями Windows. Если нужен ответ (например, какое-то приложение не удалось закрыть), окно показывается само.
* **Одна копия.** Повторный запуск не открывает вторую копию, а показывает окно уже работающей, даже из трея. После установки обновления новая версия ждёт до 15 с, пока закроется старая.
* **Журнал событий** (`%LOCALAPPDATA%\KillSwitchLauncher\events.log`, последние 500 записей): запуск и закрытие лаунчера, подключение и обрыв VPN, запуски, закрытия Kill-Switch, неудачи, заблокированные перезапуски, изменения Kill-Switch и основного подключения, обновления. Открывается из настроек (раздел «Журнал событий»). В окне: «Открыть файл» (в текстовом редакторе) и «Очистить».
* **Обновления.** Лаунчер проверяет и скачивает обновления сам (см. «Обновления» ниже). Когда найдена новая версия, на кнопке «Настройки» появляется кружок с цифрой 1, а настройки при первом открытии показывают раздел «Обновления». Версия лаунчера написана внизу списка разделов настроек.

## Где хранятся данные

`%LOCALAPPDATA%\KillSwitchLauncher\settings.json`: список приложений, состояние Kill-Switch, основное подключение и действие при закрытии окна. У каждого приложения хранится, включён ли для него журнал DNS (сами записи журнала на диск не пишутся), и его сетевые настройки: условие запуска (основное подключение, своё подключение или «Без сети»), своя защита, домены-исключения и то, дополняют они общие исключения или заменяют их. Там же общие исключения и список подключений лаунчера; ссылки, адреса подписок и конфигурации WireGuard в файле зашифрованы средствами Windows (DPAPI, значение вида `dpapi:…`): расшифровать их может только тот же пользователь на том же компьютере. Если перенести файл на другой компьютер, остальные настройки сохранятся, а ключи подключений придётся добавить заново.
`%LOCALAPPDATA%\KillSwitchLauncher\events.log`: журнал событий.
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, значение `SafeLauncher`: только если включено «Запускать вместе с Windows» (раздел «Окно и трей»). Лаунчер, запущенный так, сразу уходит в трей.
`HKLM\Software\SafeLauncher`, значение `LicenseKey`: ключ лицензии, зашифрованный для этого компьютера (см. «Ключ лицензии»). Если ключ ввели в окне лаунчера без прав администратора, он лежит в `%LOCALAPPDATA%\KillSwitchLauncher\license.dat`.
При удалении лаунчера ключ лицензии удаляется всегда, а настройки и журналы остаются, если не отметить их в окне удаления (см. «Удаление»).
Файл пишется атомарно (временный файл, затем замена). Если файл повреждён, лаунчер сохраняет его копию как `settings.json.broken` и стартует с чистыми настройками. Файл от лаунчера 1.x при первом запуске версии 2.0 копируется в `settings.json.v0.bak` и переводится в новый формат, а приложения из него переходят на основное подключение, как описано ниже.
До версии 2.3.7 был режим «Системный VPN»: приложения шли через VPN-программу на компьютере, а лаунчер следил за её адаптерами. При первом запуске 2.3.7 такие настройки копируются в `settings.json.system-vpn.bak` и переводятся: в общих настройках остаётся подключение лаунчера, основным становится прежнее подключение, а если его не было, первое из списка. Приложения «Как в общих» и со своими адаптерами переходят на основное подключение. Если подключений нет, лаунчер открывает раздел «Подключения» и предупреждает, что эти приложения не запустятся, пока подключение не добавят: напрямую они не пойдут. Если подключение есть, лаунчер один раз говорит, какие приложения через него пойдут.

## Как извлекается путь из ярлыка .lnk

`Services/ShortcutResolver.cs`:

1. Создаётся системный COM-объект **ShellLink** (CLSID `00021401-0000-0000-C000-000000000046`), тот же, которым пользуется Проводник. Ссылка на Windows Script Host (`IWshRuntimeLibrary`) не нужна.
2. Через его интерфейс `IPersistFile.Load()` загружается файл ярлыка.
3. `IShellLinkW.Resolve()` с флагами `SLR_NO_UI | SLR_NOUPDATE | SLR_NOSEARCH` и таймаутом 1 с: если цель перемещали, Windows попробует найти её, не показывая диалогов и не перезаписывая сам ярлык.
4. `GetPath()`, `GetArguments()`, `GetWorkingDirectory()` возвращают путь, аргументы и рабочую папку; переменные окружения (`%ProgramFiles%` и т.п.) раскрываются.
5. «Объявленный» (advertised) ярлык установщика MSI указывает не на файл, а на компонент продукта: путь к `.exe` берётся через `MsiGetShortcutTarget` и `MsiGetComponentPath`.
6. Ярлык приложения Microsoft Store пути к файлу не имеет: внутри него элемент папки «Приложения» (`shell:AppsFolder`). Из него берётся AppUserModelId вида `Publisher.App_8wekyb3d8bbwe!App`.

В диалоге выбора файла выставлено `DereferenceLinks = false`, иначе Windows сама подменила бы ярлык на цель и аргументы ярлыка потерялись бы.

**Лаунчер хранит сам ярлык.** При каждом запуске с плитки ярлык читается заново, поэтому если программа обновилась и ярлык теперь ведёт в другое место, лаунчер запустит то, на что ярлык указывает сейчас. Путь, аргументы и рабочая папка с прошлого запуска сохраняются в `settings.json` как запасной вариант на случай, если ярлык удалят.

**Приложения Microsoft Store** запускаются через `IApplicationActivationManager.ActivateApplication`: их процесс создаёт сама Windows и сообщает его PID. Поэтому создать такой процесс сразу внутри задания нельзя. Лаунчер забирает его в задание сразу после старта, а процессы, которые приложение успело породить за это мгновение, подбирает по папке приложения в `C:\Program Files\WindowsApps`. Папкой приложения считается папка его пакета в любой версии: обновляясь, приложение Store переезжает в папку новой версии (`Claude_1.2.0.0_x64__…` вместо `Claude_1.1.0.0_x64__…`). Иконка берётся с ярлыка так, как её рисует Проводник.

## Как распознаётся другой VPN

`Services/VpnAdapterDetector.cs` и `Services/VpnMonitor.cs`. Нужны для предупреждения под шапкой: если ядро лаунчера работает, а на компьютере включён ещё один VPN на весь компьютер, лаунчер пишет, какой, потому что два VPN могут мешать друг другу.

**Какой адаптер считается VPN.** В Windows нет признака «это VPN», поэтому используется эвристика по `NetworkInterface.GetAllNetworkInterfaces()`:

* тип `Ppp` (встроенный VPN Windows: PPTP, L2TP, SSTP, IKEv2) или `Tunnel`;
* либо ключевые слова в имени/описании: VPN, WireGuard, Wintun, TAP, TUN, OpenVPN, Cisco AnyConnect, Fortinet, GlobalProtect, Pulse/Ivanti, Check Point, SonicWall и др.;
* исключаются служебные псевдо-туннели Windows (Teredo, ISATAP, 6to4, IP-HTTPS), loopback и WAN Miniport;
* адаптер «активен», если `OperationalStatus == Up` **и** у него уже есть рабочий IP-адрес (не 169.254.x.x и не IPv6 link-local). TAP и Wintun бывают в состоянии Up до того, как туннель реально поднялся;
* адаптер ядра лаунчера в расчёт не берётся.

> **OpenVPN и «Подключение по локальной сети».** Классический OpenVPN работает через драйвер «TAP-Windows Adapter V9», а Windows по умолчанию называет этот адаптер «Подключение по локальной сети» / «Ethernet N». Это не обычная сетевая карта, а именно туннель OpenVPN. Новые версии OpenVPN 2.6+ могут использовать вместо него драйвер «OpenVPN Data Channel Offload».

**Когда проверяется.** Сразу по событиям Windows `NetworkChange.NetworkAddressChanged` и `NetworkAvailabilityChanged` (приходят при подъёме и падении туннеля) и дополнительно каждые 2 секунды по таймеру, на случай если VPN-клиент меняет состояние адаптера без смены адресов.

**Системный VPN.** До версии 2.3.7 приложения можно было пускать через VPN-программу на компьютере, а не через подключение лаунчера: лаунчер считал VPN подключённым по правилу из раздела «Адаптеры» («Любой VPN», «Один из», «Все») и пускал приложения только через эти адаптеры. В 2.3.7 режим убран из интерфейса, а настройки с ним переводятся на основное подключение (см. «Где хранятся данные»). Код режима пока остаётся и будет удалён в одной из следующих версий.

## Kill-Switch

**Почему недостаточно запомнить PID.** Ярлык Discord запускает не сам Discord, а `Update.exe --processStart Discord.exe`. Update.exe стартует Discord.exe и сразу завершается. Если помнить только PID Update.exe, через мгновение кажется, что ничего не запущено. `Process.Kill(entireProcessTree: true)` тоже не помогал: он ищет потомков по живым родителям, а у осиротевшего Discord.exe родителя уже нет. Так же ведут себя Slack, Teams classic и другие программы на Squirrel, а ещё любые программы, которые уже были открыты: новая копия передаёт управление старой и выходит.

**Как устроено:**

* **Задание Windows (Job Object).** Программа создаётся приостановленной, помещается в отдельное задание и только потом запускается. Всё, что она породит дальше (обновление, перезапуск, вспомогательные процессы), автоматически оказывается в том же задании, даже если родитель уже завершился. При обрыве VPN задание закрывается целиком одним вызовом `TerminateJobObject`; перед этим заданию запрещается создавать новые процессы, чтобы ничего не родилось в момент закрытия.
* **Подхват уже запущенного приложения.** При запуске и потом раз в секунду лаунчер ищет процессы с тем же `.exe` из папки приложения, которые работают вне задания (например, Discord из автозагрузки), и переносит их в задание. Для Squirrel-программ папкой считается общая `...\Discord`, а не `app-1.0.x`, а имя берётся и из `--processStart`. Если программа лежит прямо в общей папке (Program Files, System32, «Загрузки») или это общий «движок» (java, python, cmd), подхвата нет: под контролем только то, что запустил сам лаунчер. Чужие сеансы на терминальном сервере не трогаются. С вариантом «Через лаунчер» так же подхватываются копии приложения, которое из лаунчера не запущено (см. «Через лаунчер» ниже).
* **Блокировка повторного запуска.** После срабатывания Kill-Switch процессы закрытого приложения, которые появятся снова, закрываются сразу, пока VPN не вернётся или Kill-Switch не выключат. Об этом сообщает уведомление «Запуск без VPN заблокирован».
* **Закрытие вместе с лаунчером.** У заданий стоит флаг «закрыть процессы при закрытии задания». Если лаунчер аварийно завершится или его снимут в диспетчере задач, Windows сама закроет приложения, а не оставит их работать без защиты. Так при любых настройках: без лаунчера фильтров нет.
* **Приложение перезапустилось само.** Приложение Microsoft Store при обновлении закрывается, и Windows запускает новую версию из папки нового пакета. Новая программа не потомок прежней и в задание сама не попадает. Если процессы приложения закончились, а в течение минуты появилась его программа, запущенная не раньше этого, лаунчер считает её тем же запуском: берёт её и уже запущенные ею процессы в задание при любом варианте «Если открыто не из лаунчера», а в журнал событий пишет «Перезапустилось само (например, после обновления) и осталось под защитой». Плитка на секунду-другую становится серой и снова зелёной. Приложение, закрытое из лаунчера или Kill-Switch, так не подхватывается. В версии 2.3.7 и раньше лаунчер терял такое приложение: оно продолжало работать как копия мимо лаунчера, а копия новой версии приложения Store шла напрямую, мимо VPN.
* **Обновления Squirrel.** Если в лаунчер добавлен сам `...\app-1.0.9\Discord.exe`, а после обновления папка сменилась, лаунчер находит новую версию и запоминает путь.
* На плитке видно, сколько процессов приложения под контролем (у Discord их обычно 5–7).
* **«Завершить все процессы»** в меню плитки закрывает одно приложение так же, как Kill-Switch: задание целиком, процессы вне задания и найденные копии. Перед этим лаунчер спрашивает подтверждение, а запустить приложение снова можно сразу, без блокировки. Пункт активен, пока у приложения есть процессы под контролем.

Кроме того:

* Kill-Switch срабатывает в фоновом потоке монитора, не дожидаясь интерфейса. После этого показывается список закрытых программ и тех, что закрыть не удалось.
* Гонка «VPN упал между проверкой и стартом» закрыта: сразу после старта статус проверяется ещё раз.
* Опция находится в «Настройках» (раздел «Защита») и сохраняется. При новой установке (с версии 2.3.7) Kill-Switch выключен; если он был включён до обновления, он остаётся включённым. Выключение требует подтверждения и кнопки «Применить».
* При закрытии лаунчер предупреждает и завершает запущенные им программы.

**Kill-Switch и падение ядра.** Kill-Switch («Закрывать при обрыве») отвечает только за обрыв VPN: сервер подключения перестал отвечать. С ним приложение закрывается, и запустить его снова можно, когда VPN вернётся. Без него приложение остаётся открытым без сети и само продолжает работу, когда VPN вернётся. Трафик самого приложения мимо VPN не уходит в обоих случаях. Закрытие всё же надёжнее: пока приложение ждёт без сети, запросы, которые за него делает Windows (имена сайтов: пока VPN нет, «Защита от утечки DNS» их не ограничивает; фоновые загрузки), и программы Windows, запущенные им самим, могут идти мимо VPN (см. «Чего лаунчер не контролирует»). Падение ядра VPN обрывом не считается, и Kill-Switch в нём не участвует: ядро перезапускается (см. «Безопасность сети»).

## Журнал DNS

Показывает, к каким доменам обращается приложение, запущенное из лаунчера. Включается для каждого приложения отдельно: правый клик по плитке → «Включить журнал DNS». На плитке появляется значок «DNS», а в меню — «Открыть журнал DNS».

* **Окно журнала** не мешает работать с лаунчером и обновляется само. В строке: время, домен, тип записи (A, AAAA, HTTPS…) и процесс с PID. Переключатель «Только уникальные» показывает каждый домен один раз: сколько раз к нему обращались, какими типами и когда последний раз. Есть поиск. «Копировать» (и Ctrl+C) копирует только домены выделенных строк, по одному в строке, без времени и прочего. Национальные домены показываются буквами, а копируются как есть в DNS (`xn--…`).
* **Что попадает.** Только запросы процессов этого приложения: запущенного из лаунчера, его потомков и подхваченных копий. Чужие запросы сразу отбрасываются и нигде не хранятся. Повтор того же запроса тем же процессом в течение секунды считается одним. Новый запуск приложения, выключение и включение журнала отмечаются разделителем.
* **Хранение.** Только в памяти, последние 5000 записей на приложение (счётчики «уникальных» — за всё время). Журнал остаётся до закрытия лаунчера, даже если приложение закрыли или журнал выключили. Включён ли журнал, запоминается; запись начинается при запуске приложения из лаунчера или при включении журнала, а не при запуске самого лаунчера.
* **Права.** Запросы берутся из системного журнала событий Windows (ETW, провайдер Microsoft-Windows-DNS-Client), а для него нужны права администратора. Если лаунчер запущен от имени администратора или пользователь входит в группу «Пользователи журналов производительности» (Performance Log Users), запись идёт прямо в лаунчере. Иначе Windows один раз спросит разрешение (UAC) для помощника: это тот же `KillSwitchLauncher.exe` с ключом `--dns-collector`, без окон. Он только читает события DNS и передаёт их лаунчеру по именованному каналу, доступному лишь текущему пользователю; обе стороны проверяют, что на другом конце именно они. Когда журнал выключен у всех приложений или лаунчер закрыт (даже аварийно), помощник останавливается. Если отказать в UAC, журнал не включится, а приложение запустится как обычно.

Ограничения журнала:

* Видны только запросы через системный DNS-клиент Windows. Если программа обращается к DNS сама, минуя Windows (свой DNS-клиент, DNS over HTTPS внутри программы, как умеют браузеры), или подключается сразу по IP-адресу, таких обращений в журнале не будет.
* Процесс, который уже завершился, узнаётся ещё 10 секунд, чтобы не потерять запросы, пришедшие с опозданием.
* Журнал — инструмент наблюдения, а не защита: он ничего не блокирует.

## Безопасность сети

Главная задача лаунчера — контроль приложений, запущенных через него. Весь компьютер он не трогает: то, что действует шире, вынесено в отдельную настройку, по умолчанию выключенную, и перед её включением лаунчер объясняет, на что она повлияет.

**Защита всегда включена** (с версии 2.3.1): приложение не запускается без VPN, а его трафик мимо VPN блокируется. Настроек «Не запускать без VPN», «Блокировать трафик мимо VPN» и «Если ядро VPN упало» больше нет: без первых двух лаунчер теряет смысл, а упавшее ядро всегда перезапускается. Если они были выключены, после обновления они работают как включённые.

**Через подключение лаунчера** (ядро VPN в службе):

* Трафик приложения ядро узнаёт по заданию Windows (метка процесса, см. [core/README.md](../core/README.md)) и отправляет через подключение приложения. Остальные программы идут как обычно, напрямую.
* **«Приложения, открытые не из лаунчера»** (раздел «Защита», по умолчанию «Через VPN»). Без метки ядро узнаёт процессы приложения по его exe-файлам: те же папка и имена, по которым лаунчер подхватывает копии (для программы в общей папке вроде «Загрузок» — только сам exe). Так узнаются копия, открытая не из лаунчера (с рабочего стола, автозагрузкой, по ссылке из другой программы), и процесс самого приложения, о котором лаунчер не успел ответить ядру (на ответ у ядра полсекунды). «Через VPN» отправляет их через подключение приложения (так же их ведёт ядро и при «Через лаунчер», пока лаунчер не взял копию под контроль), «Без интернета» оставляет без сети, «Напрямую» пускает мимо VPN: тогда в такой редкий момент напрямую уходит и соединение самого приложения, отличить его от копии нельзя. Действует, пока работает ядро. Это общее значение: на странице приложения можно выбрать своё («Если открыто не из лаунчера», по умолчанию «Как в общих»). У приложения Microsoft Store ядро узнаёт его программу в папке пакета любой версии: после обновления приложения его копия идёт так же, как до него. Лаунчер узнаёт программу приложения и по подписи: программа с тем же именем exe, подписанная тем же издателем (имя владельца сертификата из проверенной Windows подписи), считается программой приложения в любой папке, кроме папки Windows. Так приложение, переустановленное или обновлённое в другую папку, остаётся своим. Сертификат издателя продлевают раз в год-три, но имя в нём остаётся; новую подпись лаунчер запоминает сам, проверяя программу приложения в фоне. Отзыв сертификата не проверяется: проверка ходила бы в интернет мимо VPN. Такую копию и процессы, которые запустила копия, открытая не из лаунчера (например, её помощник из AppData), ядро по папке приложения не узнаёт, поэтому за них отвечает лаунчер: он проверяет процесс и его родителей вверх по дереву процессов в момент соединения и отвечает ядру меткой копий, и они идут так же, как сама копия (служба ревизии 12; служба старше пускает их напрямую). Процесс, который запустило приложение под контролем, но который в задание не попал (запущен с правами администратора через окно UAC), получает метку самого приложения. Своими не считаются программы других приложений лаунчера и браузер, открытый по ссылке. Не узнаются программы Windows и служб, общие «движки» (java, cmd и подобные), программы с сетевых дисков и программы, которые есть и у приложения «Без сети»: их копии идут как остальные программы, напрямую. Копию, которую лаунчер узнаёт по папке приложения (например, программу, которая есть и у приложения «Без сети»), он показывает на плитке («без защиты») и предлагает «Перезапустить под защитой». Браузер, открытый по ссылке из другого приложения лаунчера, работает в задании того приложения, но его частью не считается: если сам браузер добавлен в лаунчер через подключение лаунчера, это тоже его копия мимо лаунчера.
* Сервер подключения проверяется перед запуском и потом каждые 15 с: ядро открывает через подключение маленькую страницу Cloudflare, а если она не открылась, сразу страницу Google. Промах засчитывается, только если не открылись обе: так недоступность одного сайта из страны сервера не выглядит обрывом. Два промаха подряд — сервер не отвечает: приложения с «Закрывать при обрыве» закрываются, остальные ждут сеть. Сразу после пробуждения компьютера и при каждой смене сети в Windows серверы проверяются вне очереди (через 3 с; несколько изменений подряд дают одну проверку). Такая проверка промахи не засчитывает, потому что сеть появляется не сразу, а вернувшийся сервер отмечает сразу.
* Ядро может не заметить, что сеть вернулась, например если компьютер уснул сразу после отключения кабеля. Тогда до перезапуска оно отвечает на любое соединение «no route to internet». Если проверка сервера не прошла, в журнале ядра после её начала есть такая строка, а у Windows есть работающий адаптер со шлюзом, виноват не сервер: ядро перезапускается с теми же настройками, работающие через него приложения на это время приостанавливаются (фильтры Windows и так не пускают их мимо адаптера ядра), промах не засчитывается. Перед запуском приложения проверка после такого перезапуска повторяется. Перезапусков не больше двух за 5 минут: если они не помогли, промахи засчитываются как обычно, а запуск отклоняется с советом закрыть и снова открыть лаунчер.
* Если сервер не ответил, а сети нет у самого компьютера (нет работающего адаптера со шлюзом), лаунчер так и пишет: «Компьютер не подключён к сети». Kill-Switch при этом работает как обычно. Отдельная проверка подключения, которую лаунчер делает, когда сервер не ответил перед запуском, в этом случае не нужна: её соединения идут через ту же сеть.
* Если у приложения уже работает копия мимо лаунчера, лаунчер сначала проверяет сервер и только потом предлагает закрыть копию и «Перезапустить под защитой»: если запустить приложение нельзя, копия остаётся открытой.
* DNS-запросы, которые приложение задаёт само (например, свой DNS-клиент браузера), ядро отправляет через подключение. Для файла WireGuard или AmneziaWG — на сервер из строки `DNS`, если он внутри туннеля.
* Исключения: сайты, которые приложение открывает напрямую, мимо подключения, вместе с поддоменами. Общие исключения задаются в разделе настроек «Исключения» и действуют для всех приложений через подключение лаунчера. На странице приложения выбирается, дополняют ли свои домены общие («Дополнять общие», по умолчанию) или заменяют их («Вместо общих»; пустой список значит, что у приложения исключений нет). Ядро узнаёт сайт по имени в TLS, HTTP и QUIC. Соединение, в котором имя сайта не узнано, идёт через подключение, так что исключения не открывают путь мимо VPN ничему, кроме перечисленных сайтов. DNS-запросы к этим сайтам задаёт системный DNS, как без лаунчера. У одного приложения вместе с общими не больше 1000 доменов: столько принимает служба, и больше не даёт сохранить ни страница приложения, ни раздел «Исключения».
* Ядро работает всё время, пока открыт лаунчер, если хоть одно приложение в настройках идёт через подключение лаунчера: так и копия приложения, открытая по ярлыку, сразу идёт как выбрано в «Приложения, открытые не из лаунчера», даже если из лаунчера ничего не запущено. Ядро запускается при открытии лаунчера, а также когда такое приложение добавлено или ему выбрано подключение лаунчера. Если ядро не запустилось, лаунчер всё равно открывается, пишет ошибку в журнал событий и показывает уведомление; приложение из лаунчера при запуске включит ядро снова.
* Пока ядро работает, через его адаптер идут и соединения остальных программ: ядро отправляет их напрямую, как без лаунчера. Выключение ядра оборвало бы их, поэтому, если приложений через подключение лаунчера в настройках не осталось, ядро выключается, только когда таких соединений нет (проверка каждые 10 с). Исключение: если через ядро шли копии убранного приложения или работающее приложение, ядро выключается сразу, иначе они продолжали бы идти через VPN. Разовые запросы DNS и времени не в счёт, а обмен по UDP ядро помнит до 5 минут после последнего пакета. При закрытии лаунчера ядро выключается сразу.
* Изменения, без которых программа пошла бы не так, как выбрано, действуют сразу, даже пока работают другие приложения: условие запуска, подключение и исключения работающего приложения, общие исключения, «Защита от утечки DNS», «Приложения, открытые не из лаунчера» и «Если открыто не из лаунчера», работающее приложение убрано из лаунчера, а у приложения, копии которого ядро узнаёт: оно добавлено или убрано, у него другое подключение, сервер или исключения. Другой сервер для таких копий ждёт, пока то же подключение использует запущенное приложение. Для этого ядро перезапускается (несколько секунд): работающие через него приложения на это время приостанавливаются, их соединения и соединения других программ через ядро обрываются, и программы подключаются заново. Если ядро с новыми настройками не запустилось, приложения, которые должны идти через него, закрываются.
* Остальные изменения ждут, пока через ядро работают приложения или идут соединения других программ: другой сервер или обновлённая подписка у запущенного приложения и у других приложений с тем же подключением (уведомление «Сервер выбран» так и пишет: подействует при следующем запуске), приложения, которые не запущены и копии которых идут напрямую, порядок плиток, IPv6 в сети. Прежние настройки в это время работают. Ядро перезапускается с ними, когда без них запускаемое приложение не пойдёт как настроено, или когда через ядро ничего не идёт.
* Подключение WireGuard или AmneziaWG связывается с сервером, только когда через него впервые что-то отправлено. Ядро держит подключения всех приложений из настроек, и без этого запуск любого из них отбирал бы связь у программы WireGuard или AmneziaVPN, в которой подключён тот же ключ. Если же приложение с этим подключением запущено, а ключ подключён и в другой программе, связь будет переходить то к одной, то к другой: для лаунчера нужен свой ключ.
* Одно и то же подключение WireGuard или AmneziaWG, добавленное дважды (тот же ключ, даже если в копии поменяли MTU или DNS), ядро ведёт одним туннелем: для сервера это один клиент, и два туннеля с одним ключом отбивали бы друг у друга связь с ним.
* «Проверить» у подключения обычно запускает отдельную копию ядра с правами пользователя: она связывается только с сервером и ничего не меняет в сети компьютера. Подключение WireGuard или AmneziaWG, которое уже работает в ядре (или такое же с тем же ключом), проверяется через само ядро: вторая копия с тем же ключом отбила бы у ядра связь с сервером, и приложения через это подключение остались бы без сети. Для этого ядро слушает на 127.0.0.1 прокси, который пускает только с ключом управления ядром (свой на каждый запуск); имя пользователя выбирает подключение. Сервер VLESS, Trojan, Shadowsocks, Hysteria2 и TUIC принимает один ключ с нескольких мест сразу, поэтому такие подключения по-прежнему проверяются отдельной копией.
* **Блокировка трафика мимо VPN** (всегда включена). Служба ставит фильтры Windows (WFP) на программы приложения: в интернет — только через адаптер ядра. Программа, которая сама выбирает обычную сетевую карту (WebRTC в браузерах и мессенджерах, привязка к адресу), не соединится. Пока ядра нет, сети у приложения нет.
* **Если ядро VPN упало**, работающие через него приложения приостанавливаются, а ядро запускается заново с теми же настройками; потом приложения продолжают работу. Попытки идут до 20 с: если упала сама служба, Windows перезапускает её через 5 с, а её фильтры всё это время на месте. Если ядро так и не запустилось или падает третий раз за 5 минут, приложения закрываются, что бы ни стояло в «Закрывать при обрыве». Если через ядро ничего не запущено, оно просто запускается заново.
* Системный прокси Windows на этом же компьютере (его включают v2rayN, Clash и подобные программы) для таких приложений закрыт: иначе браузер отдал бы трафик другой VPN-программе. Лаунчер пишет об этом в журнал и показывает уведомление. Если подключение приложения — «прокси другой программы», системный прокси не закрывается.
* Переменные окружения `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY` (и строчные) у приложений, которым нужен VPN, убираются. Исключения: программа, которую лаунчер запускает с правами администратора через окно UAC, и приложения Microsoft Store. Их запускает сама Windows, и переменные остаются; если они указывают на системный прокси, он для приложения всё равно закрыт.

**«Через лаунчер»** (вариант «Приложений, открытых не из лаунчера» и «Если открыто не из лаунчера», для любого приложения: через подключение лаунчера и без сети). Копия приложения, открытая не из лаунчера (с ярлыка, автозагрузкой, из другой программы), становится его запуском, как с плитки. Действует, пока открыт лаунчер.

* Раз в секунду лаунчер ищет копии так же, как при подхвате (те же папка и имена exe), и проверяет условие запуска: ядро работает и сервер подключения не перестал отвечать, или приложение без сети.
* Условие выполнено: копия попадает в задание вместе со всем, что она успела запустить (например, с помощником из AppData). На плитке зелёное кольцо, лаунчер показывает уведомление «Запущено» и пишет в журнал событий, Kill-Switch действует на неё так же, как на запуск с плитки, а при закрытии лаунчера она закроется вместе с ним. Через подключение лаунчера её трафик с этого момента идёт по метке приложения, как у запуска с плитки.
* Условие не выполнено: копия сразу закрывается, лаунчер показывает уведомление с причиной. Помешать Windows запустить программу лаунчер не может, поэтому окно копии может мелькнуть. В сеть она за это время не выйдет: фильтры Windows для программ приложений с этим вариантом действуют всё время, пока открыт лаунчер, а не только пока приложение работает. После срабатывания Kill-Switch, пока VPN не вернулся, копии закрываются, как и раньше («Запуск без VPN заблокирован»).
* Копии, открытые до того, как вариант начал действовать (до открытия лаунчера, в первые 30 секунд после него или до выбора варианта), не закрываются, а ждут условия запуска без сети: при входе в Windows программы из автозагрузки открываются раньше, чем подключится VPN и запустится ядро. Когда условие выполнится, лаунчер возьмёт их под контроль. Так же ждёт копия, которую лаунчер закрыть не может (работает с правами администратора).
* Сервер подключения перед этим отдельно не проверяется: если он не отвечает, это покажет обычная проверка (каждые 15 с), и приложение закроется или будет ждать сеть, как выбрано в «Закрывать при обрыве». Журнал DNS для такой копии пишет запросы, только если запись уже идёт: включать её при входе в Windows лаунчер не станет.
* Программу в общей папке (Program Files, System32, «Загрузки») лаунчер по папке не узнаёт: её копию он узнаёт, только если программа подписана, по подписи издателя (кроме программ Windows). Общий «движок» (java, cmd) не узнаётся никак. Для неузнанных копий вариант не действует: копии приложения через подключение лаунчера ядро ведёт, как при «Через VPN».

**Как устроены фильтры.** Их ставит служба, фильтры обычные, не динамические. Если служба аварийно остановится, фильтры остаются, а после её перезапуска (Windows перезапускает её через 5 с) служба одной транзакцией заменяет их наборами, сохранёнными в `run\guard.json` рядом с ней, и снимает правила программ, которые уже закрылись; лаунчер тем временем переподключается и присылает свой набор. При обычной остановке службы и при закрытии лаунчера служба снимает фильтры сама, при перезагрузке их снимает Windows. Фильтры, которые переживают перезагрузку, не используются: ошибка оставила бы программу без сети навсегда. Фильтры действуют, пока приложение запущено (а с «Через лаунчер» всё время, пока открыт лаунчер), на все его программы: exe самого приложения и каждого его процесса. Если фильтры не поставились (служба недоступна или устарела), приложение не запускается. Без лаунчера фильтров нет, поэтому приложения закрываются вместе с ним, в том числе при его сбое (перед обычным закрытием лаунчер спросит).

* Фильтр относится к файлу программы целиком. Та же программа, открытая не через лаунчер, пока приложение работает, тоже не сможет сама выбрать обычную сетевую карту: она идёт через адаптер ядра, и дальше её ведёт ядро, как выбрано в «Приложения, открытые не из лаунчера».
* **«Без сети».** Условие запуска на странице приложения и разовый пункт «Запустить без сети» в меню плитки (у приложения с «Без сети» его нет: обычный запуск и так без сети). VPN для запуска не нужен, Kill-Switch не участвует, ядро такое приложение не ведёт. Фильтр Windows пускает его программы только внутри компьютера (127.0.0.1), а системный прокси другой VPN-программы для них закрыт. Фильтр, как и у остальных, действует на программу целиком, пока приложение работает: копии той же программы в это время тоже без сети. Поэтому приложение, уже запущенное с сетью, сначала нужно закрыть, а пока оно работает без сети, обычный запуск тоже идёт без сети. Когда все его процессы закрылись, разовый запуск без сети заканчивается. Имена сайтов за приложение может по-прежнему искать служба DNS Windows, но соединиться оно никуда не сможет.
* Приложению закрыта домашняя сеть (принтеры, NAS). Внутри компьютера (127.0.0.1) сеть открыта.
* Программы Windows (`C:\Windows`), Защитника Windows и программы служб (даже остановленных) не ограничиваются: это затронуло бы весь компьютер. Лаунчер пишет об этом в журнал.

**«Защита от утечки DNS»** (по умолчанию выключена, влияет на весь компьютер; пока выключена, на главном экране метка «Возможна утечка DNS»). В Windows DNS-запросы за все программы задаёт одна системная служба, поэтому без этой настройки провайдер может видеть имена сайтов, которые открывают приложения, хотя их трафик идёт через VPN.

* Ядро отвечает на DNS-запросы условными адресами 198.18.x.x (fakeip, время жизни 1 с) и узнаёт имя сайта при соединении: у приложений лаунчера имя уходит через подключение, у остальных программ адрес ищется как обычно. Служебные имена Windows (проверка сети, `.local`, обратные зоны, имена без точки) не подменяются. На запросы записей HTTPS (браузеры спрашивают их вместе с адресом) ядро отвечает, что записей нет, а запросы остальных типов (TXT, SRV, MX и подобные, их задают редко) отправляет к DNS-серверу основного подключения через это подключение: провайдер их тоже не видит, но если подключение не отвечает, ответа на них не будет. Без основного подключения такие запросы идут к DNS компьютера.

**Когда лаунчер закрыт, всё как без VPN.** Фильтры снимаются вместе с приложениями, а приложения закрываются вместе с лаунчером. Ядро при закрытии лаунчера выключается сразу; его адаптер исчезает, кэш DNS Windows очищается. Пока лаунчер открыт, ядро может работать и без запущенных приложений (см. выше): трафик других программ идёт через его адаптер напрямую, а «Защита от утечки DNS» продолжает действовать. В системе остаётся только служба, которая без лаунчера ничего не делает.

Чего лаунчер не контролирует:

* запросы, которые за приложение делают Windows и её службы (обновления, фоновые загрузки BITS, открытие сетевых папок вида `\\адрес\папка`), и, без «Защиты от утечки DNS», имена сайтов в DNS;
* прокси, указанный в настройках самой программы (например, в Telegram);
* процессы, которые программа запустила с правами администратора через окно UAC: они не попадают в задание лаунчера, и Kill-Switch их не закроет. Через подключение лаунчера их соединения всё же идут через подключение приложения: лаунчер узнаёт их по родителю;
* программы Windows, которые запустило само приложение (например, cmd, PowerShell, curl): фильтр их не ограничивает. Обычно они идут тем же путём, что и приложение, но обойти VPN, сами выбрав сетевую карту, могут;
* программы с сетевого диска (`\\сервер\папка`): служба не может их проверить, поэтому лаунчер их не запускает и предлагает скопировать программу на компьютер.

## Ограничения

* Всё, что приложение запустило само, считается его частью, кроме браузера. Если из Discord открыть ссылку, а браузер в этот момент не был запущен, браузер окажется в задании Discord, но идёт как обычно и не закроется вместе с Discord. Если браузер уже был открыт, ссылка уйдёт в него.
* Программу, которой нужны права администратора, лаунчер без прав администратора поместить в задание и закрыть, скорее всего, не сможет: при первом запуске он об этом предупредит, а при обрыве VPN покажет её в списке «не удалось закрыть». Для таких программ запускайте лаунчер от имени администратора.
* Подхват работает раз в секунду, поэтому процесс, запущенный в обход лаунчера, может проработать до секунды. С «Через лаунчер» так же: окно копии, которую запускать нельзя, может мелькнуть, но в сеть она не выйдет.
* Другой VPN на компьютере распознаётся эвристически (см. «Как распознаётся другой VPN»), поэтому предупреждение о нём может не появиться. На защиту приложений это не влияет.
* Ядро и фильтры узнают приложение по его процессам. Запросы, которые за приложение делают системные процессы Windows, идут не от него: служба DNS Windows (без «Защиты от утечки DNS»), фоновые загрузки BITS (ими многие программы качают обновления), посредники приложений Microsoft Store, открытие сетевых папок. Отнести такие запросы к приложению нельзя, и они идут как трафик остальных программ, мимо VPN. Это ограничение подхода, а не ошибка: так устроена Windows.

## Обновления

Лаунчер обновляется из релизов GitHub: <https://github.com/psibia/safe-launcher/releases>. Всё, что касается обновлений, собрано в настройках, в разделе «Обновления»: версия, что происходит сейчас, кнопки и переключатель.

Проверка и загрузка:

* Переключатель «Автоматически проверять и скачивать обновления» включён по умолчанию. Лаунчер проверяет релизы при запуске и каждые 4 часа, а если проверка не удалась, повторяет её через час. Найденная версия сразу скачивается и проверяется. О новой версии лаунчер сообщает один раз: баннером в окне или уведомлением Windows, если окно скрыто в трей.
* «Проверить» только проверяет. Если есть новая версия, появляется кнопка «Обновить»: она скачивает версию и сразу её устанавливает. Если версия уже скачивается, «Обновить» начнёт установку сразу после загрузки. Автоматическая и ручная проверки идут одним процессом с общим состоянием: пока что-то выполняется, «Проверить» недоступна.
* Предлагаются только версии новее установленной. Черновики и пре-релизы лаунчер не видит.
* Сначала скачивается подпись установщика (файл `.exe.sig`) и сверяется с открытым ключом автора, встроенным в лаунчер. Если подпись не подходит, установщик не скачивается. Затем скачивается установщик, и его размер и SHA-256 сверяются с подписанными. Файлы лежат в `%LOCALAPPDATA%\KillSwitchLauncher\updates`, хранится только последняя версия. Скачанное в прошлый раз заново не качается, но проверяется снова.
* Если загрузка прервалась (пропала связь, нажата «Отменить загрузку» или лаунчер закрыт), скачанная часть сохраняется в файле `.part`, и следующая загрузка продолжается с того же места. Если сервер не умеет отдавать файл с середины, файл скачивается целиком.
* Если GitHub 30 секунд не присылает данные, соединение считается зависшим и разрывается. Временные сбои (нет связи, зависание, ошибка на стороне GitHub, подключение лаунчера не запустилось) лаунчер повторяет сам, без ограничения числа попыток, с паузой 5 с, 15 с, 30 с, дальше раз в минуту, пока загрузка не завершится или её не отменят. Во время паузы страница показывает причину и отсчёт до повтора. Каждая попытка заново открывает маршрут по текущим настройкам: если после «Применить» сменился способ загрузки или подключение, загрузка сразу продолжается по новому маршруту. Если выключить автоматическую загрузку, начатая сама загрузка останавливается, а начатая кнопкой «Обновить» продолжается.
* Размер и SHA-256 проверяются по всему файлу в конце. Если они не совпали, файл удаляется и скачивается заново один раз. Если не совпали снова или не сошлась подпись, загрузка останавливается, и эта версия сама больше не скачивается (кнопка «Обновить» попробует снова). Нехватка места на диске тоже останавливает загрузку без повторов.
* Если GitHub ответил, что файла нет (404), лаунчер сверяется со списком релизов. Релиз удалён и новых версий нет: загрузка останавливается, скачанное удаляется. Опубликована другая версия: лаунчер качает её.
* Перед установкой скачанной версии «Обновить» сверяется со списком релизов. Релиз удалён: версия не ставится, скачанное удаляется. Вышла версия новее: скачивается и ставится она. Если GitHub недоступен, ставится скачанная версия: она уже проверена.
* На странице видно каждый шаг: «Проверка обновлений», загрузка с полосой, объёмом, скоростью и оставшимся временем, «Проверка подписи». Ошибка показывается красной строкой с причиной и тем, когда будет следующая попытка.
* Когда найдена новая версия, на кнопке «Настройки» и у раздела «Обновления» появляется отметка, скачана версия или нет. Следующее открытие настроек сразу ведёт в раздел «Обновления», один раз для каждой версии. Скачанная и проверенная версия показана как «Версия X готова к установке».
* «Что нового» показывает описание релиза с GitHub: новой версии, а если обновления нет, установленной.
* В «Дополнительно» выбирается, как скачивать: напрямую (по умолчанию) или через подключение лаунчера, для сетей, где GitHub недоступен. Если выбранное подключение не запущено, лаунчер запускает его на время проверки и загрузки.
* Переключатель автоматической проверки и способ загрузки, как и остальные настройки, вступают в силу по «Применить».

Установка:

* «Обновить» начинает установку, только когда закрыты все приложения с плиток: запущенные из лаунчера и их копии, запущенные мимо него (у текущего пользователя). Если приложения работают, страница показывает их список и кнопку «Закрыть приложения и обновить». Она закрывает их, как крестиком, и установка начинается сама, когда закроются все. Приложение, которое за 15 секунд не закрылось (например, спрашивает о несохранённых данных), названо в списке, и для него есть «Закрыть принудительно». Закрыть приложения можно и самим.
* Лаунчер останавливает своё подключение и передаёт скачанные файлы службе «Безопасный лаунчер — сеть». Служба ещё раз проверяет подпись и версию (только новее своей), копирует установщик в папку `C:\Program Files\SafeLauncher\update`, куда могут писать только администраторы, сохраняет там копию текущей версии для отката (папки лаунчера и службы, запись об установке) и запускает помощника `SafeLauncher.Updater.exe`. Затем лаунчер закрывается, а вместо него открывается окно «Обновление до версии …».
* Помощник ждёт, пока лаунчер закроется, проверяет подпись, останавливает службу и ядро и запускает установщик без окон (`/VERYSILENT /autoupdate=1 /service=1`). После установки он проверяет результат: версии файлов лаунчера и службы, ядро на месте, служба запущена и отвечает. Если что-то не так, помощник возвращает прежнюю версию из копии и запускает прежнюю службу.
* Затем окно ожидания запускает новую версию лаунчера, а помощник ждёт от неё сообщения, что она запустилась. Лаунчер сообщает об этом службе, когда его окно открылось и он готов к работе. Если новая версия закрылась и за 15 секунд не появилась снова или за 90 секунд после запуска так и не сообщила о себе, помощник закрывает её и возвращает прежнюю версию. Если за 2 минуты лаунчер никто не запустил, обновление считается установленным без этой проверки. Эту проверку выполняет помощник прежней версии, поэтому она работает при обновлении с версии 2.3.6 и новее.
* Окно ожидания показывает шаги установки и сколько прошло времени. Оно закрывается, когда новая версия сообщила о запуске (при обновлении с версий до 2.3.6, когда появилось её окно). Новая версия открывается на том же месте, того же размера и на той же странице, что и перед обновлением, если окно не было скрыто в трей, и сообщает «Обновлено до версии …» с кнопкой «Что нового». Если обновление не встало, запускается прежняя версия и одной строкой сообщает, что обновиться не удалось. Причина записывается в технический журнал, полный журнал установки лежит в `C:\Program Files\SafeLauncher\update\update.log`.
* Запроса прав Windows при этом нет. По-старому, установщиком с запросом прав и без отката, обновление ставится, если у релиза нет подписи, в лаунчер не встроен ключ, лаунчер установлен не в Program Files или служба не умеет ставить обновления. Последнее касается первого обновления с версий, где этой схемы ещё не было: следующие обновления уже ставятся через службу.
* Ключ лицензии при обновлении не спрашивается: его хранит компьютер. Только лаунчер версии 2.3.2 и раньше при первом запуске после обновления один раз спросит ключ в своём окне (см. «Ключ лицензии»).

Ключ подписи выпусков:

* `installer\build-installer.cmd` при первом запуске создаёт пару ключей ECDSA P-256: закрытый `installer\update-signing-key.pem` и открытый `installer\update-public-key.pem`. В конце каждой сборки он подписывает установщик: рядом появляется `SafeLauncher-Setup-<версия>.exe.sig` (версия, имя, размер и SHA-256 установщика и подпись).
* Закрытый ключ есть только на компьютере, где собираются выпуски: он в `.gitignore`. Сохраните его копию отдельно. Без него новые выпуски не подписать, а установленные лаунчеры принимают только выпуски, подписанные этим ключом. Новый ключ создать нельзя: сборка остановится и попросит вернуть прежний из копии.
* Открытый ключ добавьте в Git: при сборке он встраивается в лаунчер и службу (`SafeLauncher.Logging`).

Как выкладывать релиз:

1. Поднимите `<Version>` в `KillSwitchLauncher.csproj`, `SafeLauncher.Service.csproj` и `SafeLauncher.Logging.csproj` (одинаково) и соберите установщик (`installer\build-installer.cmd`, нужны `installer\license-hashes.txt` и ключ подписи).
2. На GitHub создайте релиз с тегом `v2.4.0` (или `2.4.0`), версия в теге должна совпадать с `<Version>`.
3. Приложите к релизу оба файла из `installer\Output`: `SafeLauncher-Setup-2.4.0.0.exe` и `SafeLauncher-Setup-2.4.0.0.exe.sig`. Лаунчер берёт первый `.exe`, в имени которого есть `Setup`, и подпись с тем же именем и `.sig` в конце.
4. Описание изменений пишите в описании релиза, Markdown поддерживается: заголовки, списки, **жирный**, `код`. Ссылки показываются текстом.

Репозиторий должен быть публичным: лаунчер обращается к GitHub без входа в аккаунт (лимит GitHub для этого — 60 запросов в час с одного IP).

## Установщик

В папке `installer` лежат скрипт Inno Setup (`KillSwitchLauncher.iss`), `build-installer.cmd` и `prepare-core.ps1`.

1. Один раз установите [Inno Setup 6](https://jrsoftware.org/isdl.php) и .NET 8 SDK и положите в папку `installer` файл `license-hashes.txt` с хешами ключей лицензии (см. «Ключ лицензии»).
2. Запустите `installer\build-installer.cmd`. Он:
   * публикует лаунчер в `installer\publish` (Release, win-x64, self-contained, один exe);
   * публикует службу в `installer\publish-core` (тоже один exe со встроенным .NET) и кладёт рядом ядро `launcher-core.exe` нужной версии и файлы его лицензии. Ядро берётся готовым: `installer\launcher-core.exe`, уже установленное в `C:\Program Files\SafeLauncher\core`, `prototype\RouteCheck\bin\launcher-core.exe` или архив `launcher-core.zip` там же. Если подходящего нет, ядро собирается скриптом `core\build.ps1` (нужны Git и Go);
   * собирает установщик;
   * подписывает его ключом подписи выпусков, а при первой сборке сначала создаёт этот ключ (см. «Обновления»).
3. Готовые файлы: `installer\Output\SafeLauncher-Setup-<версия>.exe` и его подпись `SafeLauncher-Setup-<версия>.exe.sig`.

Что делает установщик:

* при первой установке спрашивает ключ лицензии и передаёт его лаунчеру; лаунчер проверяет ключ при каждом запуске (см. «Ключ лицензии»);
* ставит лаунчер для всех пользователей в `C:\Program Files\Безопасный лаунчер` (нужны права администратора), а службу «Безопасный лаунчер — сеть» и ядро — в `C:\Program Files\SafeLauncher\core`. Служба запускается вместе с Windows и без лаунчера ничего не делает;
* создаёт ярлык в меню «Пуск» и по желанию на рабочем столе, предлагает запустить лаунчер (от имени обычного пользователя);
* перед заменой файлов ждёт, пока закроется лаунчер, и останавливает службу, а после установки регистрирует службу заново;
* при обновлении с версии 1.x, установленной «только для меня» (в AppData), удаляет ту копию; настройки сохраняются;
* при обновлении через службу (`/autoupdate=1 /service=1`) работает без окон от имени системы, не запускает лаунчер (это делает окно ожидания обновления) и не трогает папку `C:\Program Files\SafeLauncher\update` с копией для отката;
* при удалении останавливает и удаляет службу, убирает автозапуск лаунчера, журналы службы и ядра (`%ProgramData%\SafeLauncher\logs`) и ключ лицензии, а настройки и журналы лаунчера удаляет, только если их отметить (см. «Удаление»).

.NET 8 на компьютере не нужен. Версия берётся из `<Version>` в `KillSwitchLauncher.csproj`.

Windows SmartScreen может предупреждать о неизвестном издателе, потому что установщик не подписан: «Подробнее» → «Выполнить в любом случае».

### Удаление

После вопроса «Вы действительно хотите удалить…?» установщик спрашивает, что удалить вместе с лаунчером. Обе галочки по умолчанию сняты:

* «Удалить настройки»: всё из `%LOCALAPPDATA%\KillSwitchLauncher`, кроме журналов (приложения, подключения, подписки, резервные копии настроек).
* «Удалить журналы»: журнал событий (`events.log`) и технический журнал с отчётами о сбоях (папка `logs`).

Данные удаляются у всех пользователей компьютера (по списку профилей Windows). Ключ лицензии удаляется всегда, в том числе без отметок и при удалении без окон (`/SILENT`, `/VERYSILENT`): при повторной установке его спросят снова. Настройки и журналы без отметок остаются. «Отмена» в этом окне прерывает удаление.

### Ключ лицензии

Лаунчер работает только по ключу лицензии вида `XXXXX-XXXXX-XXXXX-XXXXX-XXXXX` (латинские буквы без I и O, цифры от 2 до 9). Ключ проверяет сам лаунчер при запуске, без обращения к сети. Исходный код открыт, поэтому самих ключей в репозитории нет:

* `installer\license-hashes.txt` содержит SHA-256 каждого ключа, записанного заглавными буквами без дефисов, по одному в строке; строки с `;` считаются комментариями. Файл есть только у того, кто собирает установщик, и указан в `.gitignore`. Без него `build-installer.cmd` и компиляция установщика останавливаются с ошибкой, а лаунчер собирается с предупреждением и не принимает ни один ключ.
* Хеши встраиваются и в лаунчер, и в установщик. Введённый ключ проверяется по хешу; регистр букв и дефисы не важны.
* Принятый ключ хранится зашифрованным средствами Windows для этого компьютера (DPAPI): `HKLM\Software\SafeLauncher`, значение `LicenseKey` (для всех пользователей, записывает установщик), либо `%LOCALAPPDATA%\KillSwitchLauncher\license.dat` (если ключ ввели в окне лаунчера без прав администратора). На другом компьютере эта запись не подойдёт. От пароля пользователя, домена и сети она не зависит, работу Windows не меняет.
* С сохранённым ключом обновления, в том числе из самого лаунчера, ставятся без вопроса о ключе. Ключ удаляется при удалении лаунчера (всегда).

Где спрашивается ключ:

* при обычной установке: первая страница мастера «Ключ лицензии». Установщик передаёт ключ лаунчеру, и при запуске он не спрашивается;
* при обновлении из лаунчера версии 2.3.2 и раньше (ключ ещё не сохранён): лаунчер спросит его в своём окне при первом запуске после обновления;
* при установке без окон (`/SILENT`, `/VERYSILENT`): параметр `/KEY=XXXXX-XXXXX-XXXXX-XXXXX-XXXXX`. Без него или с неверным ключом установщик завершается с кодом 1 (кроме обновления из лаунчера: оно поставится, а ключ спросит сам лаунчер).

Чтобы добавить ключ, допишите его хеш в `license-hashes.txt` и соберите установщик. Хеш считается так (PowerShell):

```powershell
$key = 'XXXXX-XXXXX-XXXXX-XXXXX-XXXXX'.Replace('-', '').ToUpperInvariant()
-join ([Security.Cryptography.SHA256]::Create().ComputeHash([Text.Encoding]::ASCII.GetBytes($key)) | ForEach-Object { $_.ToString('x2') })
```

Чтобы отозвать ключ, удалите его хеш и выпустите новую версию: после обновления лаунчер перестанет принимать этот ключ и спросит другой.
