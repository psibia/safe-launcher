# Ядро VPN

Встроенный VPN лаунчера работает на [sing-box](https://github.com/SagerNet/sing-box) с тремя небольшими правками.
Лаунчер не связан с авторами sing-box и не представляет их проект; ядро поставляется отдельной программой `launcher-core.exe`.

## Что изменено

Без правки sing-box различает программы только по пути к exe-файлу. Тогда Discord, запущенный из лаунчера,
и тот же Discord, открытый с рабочего стола, неотличимы. Правка ([patches/0001-safe-launcher-owner.patch](patches/0001-safe-launcher-owner.patch))
добавляет один вопрос к лаунчеру:

- ядро запускает служба «Безопасный лаунчер — сеть» ([SafeLauncher.Service](../SafeLauncher.Service)) по команде лаунчера, с переменными окружения `SAFE_LAUNCHER_OWNER_PIPE` (имя именованного канала лаунчера) и `SAFE_LAUNCHER_OWNER_PID` (PID лаунчера);
- для каждого нового соединения ядро определяет PID процесса, как и раньше, и спрашивает у лаунчера по каналу, чей он;
- лаунчер отвечает меткой приложения, если процесс входит в задание Windows (Job Object) этого приложения, то есть запущен из лаунчера или порождён таким процессом;
- тогда путь процесса для правил выглядит как `launcher:<метка>|<настоящий путь>`, и правило `process_path_regex` вида `^launcher:discord\|` выбирает именно его;
- ядро подключается только к каналу, сервер которого — процесс с PID из `SAFE_LAUNCHER_OWNER_PID`; если лаунчер недоступен, путь остаётся обычным;
- ответ про процесс приложения ядро запоминает (по PID и времени запуска процесса, ведь PID повторяются): если лаунчер не ответил вовремя, такой процесс остаётся со своим приложением, а не уходит напрямую. Секунду после такой ошибки знакомые процессы не ждут лаунчер, остальные спрашивают его как обычно;
- метку получают только процессы того же сеанса Windows, что и лаунчер: лаунчер одного пользователя не может присвоить процессы другого;
- метка — только латинские буквы, цифры, `-` и `_`, не длиннее 64 символов, иначе ответ не принимается.

Протокол канала: запрос — PID (uint32, little endian); ответ — длина метки (uint16) и метка в UTF-8, длина 0 означает «не наш процесс».

## Где лежит ядро

Ядро и служба ставятся в `C:\Program Files\SafeLauncher\core`: туда пишут только администраторы, а служба работает от имени системы.
В пути не должно быть русских букв: при строгой маршрутизации ядро разрешает DNS только себе правилом брандмауэра,
привязанным к пути exe, и с русскими буквами в пути это правило не срабатывает — у всего компьютера пропадает DNS
(проверено на прототипе, см. [prototype](../prototype/README.md)).

Эта правка касается только Windows (`common/process/searcher_windows.go` и новый `common/process/launcher_owner_windows.go`).

Вторая правка ([patches/0002-sniff-override-destination.patch](patches/0002-sniff-override-destination.patch)) возвращает
в действие правила `sniff` параметр `override_destination`. Приложение сначала узнаёт адрес сайта у DNS, а потом подключается
по этому адресу. С параметром ядро берёт имя сайта из самого соединения и отдаёт серверу VPN имя, а не адрес. Тогда
сайт откроется по адресу, который виден из страны сервера, даже если адрес, полученный приложением, устарел или
подменён провайдером. Служба включает параметр для соединений приложений лаунчера.

Третья правка ([patches/0003-wireguard-optional-ipv6.patch](patches/0003-wireguard-optional-ipv6.patch)) касается WireGuard.
Ядро привязывает сокеты WireGuard к основной сетевой карте. Если на ней выключен IPv6 (так бывает в корпоративных сетях),
Windows не даёт привязать сокет IPv6, и без правки WireGuard не открывал и сокет IPv4: подключение молчало («Timeout»).
С правкой WireGuard в таком случае работает только по IPv4.

## Сборка

Нужны Git и Go. Скрипт скачает исходники sing-box версии v1.14.3, применит правки и соберёт `launcher-core.exe` версии `1.14.3-safelauncher.6`:

```powershell
.\core\build.ps1
```

## Лицензия

sing-box распространяется по GNU GPL версии 3 или новее, поэтому и `launcher-core.exe` распространяется по GPL-3.0-or-later.
Исходный код ядра — это исходники sing-box v1.14.3 (https://github.com/SagerNet/sing-box/tree/v1.14.3) с правками из папки `patches`;
скрипт `build.ps1` воспроизводит сборку. Сам лаунчер — отдельная программа под лицензией Apache 2.0 (см. LICENSE в корне),
с ядром он общается через командную строку и именованный канал.
