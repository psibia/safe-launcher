# Стенд ядра VPN

Проверяет ядро лаунчера (`launcher-core.exe`, sing-box с правками из `core/patches`) одной командой на Linux: собирает ядро
из `core/` так же, как `core/build.ps1`, поднимает тестовые серверы AmneziaWG, WireGuard и VLESS и гоняет через ядро
несколько «приложений» сразу. Нужен прежде всего при обновлении sing-box: поменяли версию в `core/build.ps1` или правки
в `core/patches`, запустили стенд, увидели «ВСЁ ПРОШЛО» или список того, что сломалось.

Стенд никуда не ходит, кроме загрузки исходников (sing-box с GitHub, модули Go): серверы и приложения живут в двух
сетевых пространствах Linux на одном компьютере, адреса из диапазонов для документации и частных сетей.

## Что проверяет

Одно ядро с настройками, как их строит служба лаунчера (адаптер TUN, маршруты по программам, DNS каждого приложения через
его подключение), ведёт несколько приложений, у каждого своё подключение:

| Подключение | Что это |
|---|---|
| A | AmneziaWG 3.1 (сервер на amneziawg-go v3.1.20260828) |
| B, E | обычный WireGuard (amneziawg-go v0.2.19 без настроек AmneziaWG) |
| C | AmneziaWG 1.0 (amneziawg-go v0.2.12) |
| D | VLESS (второе ядро sing-box в роли сервера) |
| direct | программа вне лаунчера, идёт напрямую |

Каждое приложение по кругу ищет имя через DNS, получает приветствие своего сервера по HTTP, скачивает, загружает и
обменивается пакетами UDP. Шаг проходит, если все приложения получили ответы именно своих серверов, без потерь.

Шаги полного прогона (`bench.sh --list` покажет актуальный список):

| Шаги | Что проверяют |
|---|---|
| `service-config` | настройки ядра, которые строит сама служба (`CoreConfigBuilder`, программа `cfgcheck/`), принимает новое ядро (`sing-box check`) |
| `mixed`, `mixed-reversed`, `awg-and-vless`, `awg-and-wg` | несколько подключений разных типов одновременно, вместе с программой вне лаунчера |
| `hide-dns`, `rare-dns`, `hide-dns-via-main`, `hide-dns-via-shared` | «Скрывать DNS-запросы»: подмена адресов, редкие запросы, DNS через основное подключение |
| `restart` | перезапуск ядра, пока все передают данные: после него всё снова работает (строки `BAD` про раунды, оборванные самим перезапуском, ожидаемы) |
| `bad-amnezia` | неверные настройки AmneziaWG: ядро объясняет причину и не выдаёт закрытый ключ |
| `first-A` … `first-D` | первые пакеты сразу после запуска ядра |
| `same-address-*` | подключения с одинаковым адресом в туннеле и много потоков UDP сразу (правка sing-tun 0001) |
| `wg-then-vless`, `vless-then-wg` и подобные | второе приложение запускается, пока первое передаёт данные; `*-new-core` с перезапуском ядра |
| `idle-keepalive` | подключение WireGuard без работающего приложения не трогает свой сервер (правка wireguard-go 0002) |
| `check-via-core-http`, `-http-pre`, `-socks` | «Проверить подключение» при работающем ядре, как в `ConnectionTester` (программа `probe/`) |
| `outside-copies` | копии приложения, запущенные мимо лаунчера: «Через VPN», «Блокировать», «Разрешить» |
| `port-taken` | порт ядра занят другой программой: ядро не запускается и говорит почему |
| `hold-ABCD` … `hold-DCBA` | все 24 порядка запуска четырёх приложений: долгие соединения не обрываются |

Наблюдения `core-stop-direct`, `connections-api`, `connections-api-hide-dns`, `check-separate` ничего не проверяют, только
печатают, что происходит. В полный прогон не входят, запускаются по имени.

## Что нужно

- Linux или WSL2 (в Windows напрямую не работает: нужны сетевые пространства Linux).
- Права root: стенд создаёт сетевые пространства `srv` и `cli` и адаптер TUN (`/dev/net/tun`).
- `iproute2` (команда `ip`), `git`, Python 3.8 или новее.
- Go любой версии 1.21 или новее с доступом в интернет: нужную версию Go (`$env:GOTOOLCHAIN` в `core/build.ps1`) он скачает сам.
- По желанию .NET 8 SDK (`dotnet`): без него шаги `service-config` и `check-via-core-*` пропускаются.

В Ubuntu или Debian (и в WSL2 с Ubuntu): `sudo apt install iproute2 git python3 golang` (если Go из пакетов старше 1.21,
поставьте его с go.dev). .NET 8 SDK ставится по инструкции Microsoft для вашего Linux.

## Как запускать

Из корня репозитория:

```
sudo bash tools/core-bench/bench.sh                    # полный прогон
sudo bash tools/core-bench/bench.sh mixed restart      # только эти шаги
bash tools/core-bench/bench.sh --list                  # список шагов
```

Если `dotnet` или Go стоят не в системных папках, передайте путь: `sudo env PATH="$PATH" bash tools/core-bench/bench.sh`.

Первый прогон долгий: скачивание и сборка ядра, серверов и программ .NET. Ядро пересобирается, только если изменились
`core/build.ps1` или правки в `core/patches`. Сами шаги полного прогона идут около 12 минут.

Итог в последней строке: `ВСЁ ПРОШЛО` или `НЕ ПРОШЛИ: <шаги>`, затем пропущенные шаги и папка журналов. При сбое код
выхода 1. В папке журналов настройки ядра каждого шага (`core-<шаг>.json`), журнал ядра (`core-<шаг>.log`), журналы
серверов и результаты приложений.

Рабочая папка `/tmp/core-bench`, другую можно задать переменной `CORE_BENCH_WORK`. В репозитории сборка .NET оставляет
только папки `bin` и `obj` (они в `.gitignore`).

## Состав

| Файл | Что делает |
|---|---|
| `bench.sh` | проверяет права и инструменты, собирает всё нужное, запускает `run.py` |
| `build-core.sh` | собирает ядро для Linux: версию sing-box, правки, теги сборки и версию Go берёт из `core/build.ps1` |
| `run.py` | шаги стенда: сети, серверы, настройки ядра, приложения, итог |
| `app.py` | тестовое «приложение» (у каждого своя копия Python: ядро различает приложения по пути программы) |
| `httpsrv.py` | сервер HTTP и эха UDP для прямого маршрута и VLESS |
| `awgserver/` | сервер AmneziaWG и WireGuard, общий исходник и свои `go.mod` для каждой версии amneziawg-go |
| `probe/` | запросы через прокси проверки так же, как `ConnectionTester` лаунчера |
| `cfgcheck/` | настройки ядра от `CoreConfigBuilder` службы для шага `service-config` |

## Что держать в согласии с кодом

- `build_config` в `run.py` повторяет правила `CoreConfigBuilder.Build` службы. Изменили правила в службе, повторите их
  здесь. Сами настройки службы проверяет шаг `service-config`, а остальные шаги идут на настройках из `run.py`.
- Отличия от Windows: приложения различаются по папке программы, а не по метке лаунчера (правка 0001 работает только
  в Windows), и `strict_route` выключен (строгим маршрутам нужен IPv6, которого может не быть).
- Концы строк: скрипты `.sh`, `.py`, `.go` и `go.mod`, `go.sum` хранятся с LF (см. `.gitattributes` в этой папке),
  иначе bash в WSL2 их не запустит.
