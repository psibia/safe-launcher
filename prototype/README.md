# Прототип: VPN только для программ из лаунчера

Проверка встроенного VPN до того, как строить на нём лаунчер. `RouteCheck.exe` пользуется службой и ядром
([core](../core/README.md)) так же, как будет лаунчер: с обычными правами, через службу «Безопасный лаунчер — сеть»
([SafeLauncher.Service](../SafeLauncher.Service)), которая от имени системы запускает ядро.

Настоящий VPN-сервер не нужен. Его изображает вторая копия ядра на этом же компьютере: прокси SOCKS5 на 127.0.0.1,
который лаунчер получает как подключение. По журналу этого «сервера» видно, чьи соединения через него прошли.

## Как запустить

1. Откройте `prototype\RouteCheck\bin` и запустите `RouteCheck.exe`.
2. Если служба ещё не установлена или установлена другая версия, Windows спросит права администратора: согласитесь.
   Служба и ядро копируются в `C:\Program Files\SafeLauncher\core`, как это будет делать установщик.
3. Подождите пару минут. На время проверки интернет может пропасть на несколько секунд.
4. Внизу окна будет итог «ВСЁ РАБОТАЕТ» или «ЕСТЬ ПРОБЛЕМЫ». Подробности — в `RouteCheck-report.txt` рядом с программой.

Другой VPN на время проверки лучше выключить. Удалить службу: `RouteCheck.exe --uninstall-service`.

## Что проверяется

Подопытная программа — сама `RouteCheck.exe` с ключом `--probe`. Она выходит в сеть пятью способами: HTTP, TLS
(к серверу dns.google), DNS-запрос по UDP, запрос времени (NTP) по UDP и поиск имени через системный DNS Windows.
Связь засчитывается только по ответу сервера. «Программа лаунчера» — такая же копия в задании Windows, как это делает лаунчер,
она ещё и запускает дочернюю копию; ходит она на другие адреса тех же служб, чем «чужая программа», чтобы их соединения
различались в журнале сервера. Сайт dns.google у программы лаунчера в исключениях — к нему она должна ходить напрямую.

| Этап | Ожидается |
|---|---|
| Служба | Установлена эта версия и работает; лаунчер связался с ней без прав администратора |
| A. Без ядра | Связь есть у всех. Способы, которые не работают уже здесь, дальше не учитываются |
| B. Подключение работает | Программа лаунчера и её дочерний процесс выходят в сеть через тестовый сервер, к dns.google — напрямую. Чужая программа — напрямую, на сервер не попадает |
| C. Подключение не работает | Сервер «выключен»: у программы лаунчера и её дочернего процесса нет сети, кроме dns.google. Чужая программа работает |
| D. Вторая копия лаунчера | Не может перезапустить ядро, которым пользуется первая; ядро первой продолжает работать |
| E. Выход из лаунчера | Ядро закрылось само, адаптер «SafeLauncher» исчез, связь у всех напрямую |
| F. Лаунчер упал | Копию-«лаунчер» завершают принудительно: служба сама останавливает ядро, адаптер исчезает |

Системный DNS для программы лаунчера только показывается: имена ищет служба Windows, а не сама программа,
поэтому по процессу такие запросы к приложению не отнести.

Если что-то не так, отчёт объясняет, на каком шаге: ядро не спросило лаунчер, спросило о другом процессе,
лаунчер не узнал процесс или правило не сработало. В конце отчёта — журналы ядра и тестового сервера.

## Сборка

```powershell
dotnet publish prototype\RouteCheck -c Release -r win-x64 --self-contained false -o prototype\RouteCheck\bin
dotnet publish SafeLauncher.Service -c Release -r win-x64 --self-contained false -o prototype\RouteCheck\bin\service
.\core\build.ps1   # launcher-core.exe в bin (или архивом launcher-core.zip — RouteCheck распакует сам)
```
